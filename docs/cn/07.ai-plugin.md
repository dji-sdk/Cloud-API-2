## 第一部分：AI Plugin 使用指南

---

### 第一章：产品介绍

#### 1.1 这是什么

- **cloudapi2-ai-plugin**是大疆上云 API 2 官方发布的 AI Plugin，安装在Claude Code等AI编程工具中即可使用。
- 它把资深工程师的无人机开发工程规范沉淀为可自动触发的能力，让 AI 编程助手不再"上来就写代码"，而是结合无人机业务知识**先想清、再动手**。
- 产品由四部分组成：**13 个 Skill**（教 AI 写对代码 / 部署 / 排障）+ **6 个快捷指令**（一键生成前端组件接入代码）+ **MCP Server**（让 AI 运行时直接操控设备） + **知识库**（llms.txt 领域文档索引，可独立使用）。

---

#### 1.2 能帮你做什么

Plugin 覆盖上云 API 2 的以下业务方向：

| 方向                    | 覆盖内容                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| **后端 SDK 集成**       | SDK 初始化、鉴权、飞控、任务、直播、媒体、错误码                                                                |
| **前端组件接入**        | 驾驶舱、设备小窗、航线编辑 / 预览、飞行记录、直播大屏、设备管理 7 大前端组件                                    |
| **设备管理**            | 设备列表、状态订阅、HMS 告警、固件升级、上下线事件，以及机场控制、设备调试、日志、维修工单、RTK 标定等运维模块  |
| **实时遥测（SEI/OSD）** | 帧级位置数据、Cesium 视锥可视化、视频投影                                                                       |
| **地图域**              | 自定义飞行区（限飞区 / 作业区 / 禁降区）、离线地图、解锁证书、地图元素                                          |
| **PSDK 负载域**         | 探照灯、喊话器（含音频上传）、PSDK Widget、浮窗文本                                                             |
| **AI 域**               | AI Box 应用、机载 AI 识别与跟踪、AI 主动告警、机载算法管理、AI 目标检测告警                                     |
| **MCP 工具调用**        | 让 AI Agent 通过自然语言操控无人机 / 机场，覆盖设备、航线任务、实时指挥、媒体、空域、相机与负载等 14 个业务模块 |
| **部署引导**            | MCP Server / Skeleton 半自动部署到自有环境                                                                      |
| **知识库入库**          | 外部文档一键收录到 knowledge/ 并维护索引                                                                        |
| **排障诊断**            | 本地日志采集与脱敏、4 阶段 RCA + 错误码字典、自然语言反馈问题 / 需求 / 咨询等                                   |

**Plugin 可以帮你：**

- ✅ **代码生成**：一键生成前端组件的完整 HTML 接入代码 / 后端 Java Service 代码
- ✅ **规范约束**：自动加入鉴权头注入与 initialize 检查、listen/cancel 配对、控制权释放、危险操作风险提示等大疆专属硬性约束
- ✅ **错误诊断**：本地采集与脱敏 + 4 阶段 RCA + 错误码字典，快速定位 SDK / 前端问题
- ✅ **运行时操控**：搭配 MCP Server，让 AI 用自然语言直接创建航线任务、查询设备遥测、控制无人机
- ✅ **半自动部署**：MCP Server / Skeleton 逐步引导（AI 生成命令，用户负责执行）
- ✅ **知识收录**：外部文档一键收录到 knowledge/ 知识库并维护索引
- ✅ **接入排障**：解决跨域、Mixed Content、Whistle 代理、初始化时序等常见接入问题

---

#### 1.3 适用人群

- 正在接入上云 API 2 的 **开发者**（后端 Java + 前端 Web）

### 第二章：安装 Plugin

#### 2.1 安装前准备

开始安装前，请确认以下已就绪：

- **Claude Code CLI ≥ v1.0**（`claude --version` 查看）

---

#### 2.2 安装步骤

```
# 方式 1：Claude Code Plugin 一键安装（推荐）
claude plugin marketplace add dji-sdk/Cloud-API-2
claude plugin install cloudapi2@dji

# 方式 2：npx skills add（自动检测 IDE）
npx skills add https://github.com/dji-sdk/Cloud-API-2

# 方式 3：手动拷贝
cp -r skills/cloudapi2-sdk-core ~/.claude/skills/    # Claude Code
```

---

#### 2.3 验证安装是否成功

安装完成后，可通过以下任意方式进行验证：

**方法 A：查看已安装列表**

在 Claude Code 会话中输入：

```
/plugins
```

输出中应包含 `cloudapi2@dji (enabled)`。

**方法 B：测试指令补全**

在 Claude Code 中输入 `/cloudapi2:`，如果弹出以下 6 个补全选项，说明快捷指令已注册：

- `wayline`
- `cockpit`
- `device`
- `device-window`
- `multi-stream`
- `replay`

**方法 C：发一条测试消息**

在 Claude Code 中发送：

帮我写一下初始化 DJI Cloud API 2 SDK代码

Claude 应自动触发 cloudapi2-sdk-core Skill，回复中应提到 "鉴权头注入""initialize 返回值必须检查" 等关键词。

#### 2.4 在线 DEMO

想先看看 Demo 的效果，可查阅[无人机管理平台使用说明](./11.demo/01.usage.md)。

#### 2.5 升级 / 卸载 Plugin

**升级**：收到新版压缩包后，先卸载旧版，再下载新的AI Plugin文件重新安装。

**卸载**：

```bash
claude plugin uninstall cloudapi2@dji

```

### 第三章：如何使用 Plugin

Plugin 提供 **3 种使用方式**，可根据场景灵活选择。

---

#### 3.1 方式一：直接对话

**直接用自然语言说出你的需求**，Claude 会根据关键词自动加载对应 Skill，生成代码或给出解答。

**示例对话：**

| 你的问题 / 需求                              | 触发的 Skill                   | Claude 能做什么                                                                                          |
| -------------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| "帮我写一下初始化 DJI Cloud API 2 SDK 代码"  | `cloudapi2-sdk-core`           | 生成含鉴权头注入、initialize 返回值检查的 Java 代码                                                      |
| "订阅无人机遥测数据的代码"                   | `cloudapi2-sdk-core`           | 生成 listen/cancel 配对的订阅代码                                                                        |
| "让无人机返航 / 起飞 / 紧急停机的代码"       | `cloudapi2-sdk-core`           | 生成飞控代码，附控制权 acquire/release 闭环 + 风险提示                                                   |
| "帮我写一个驾驶舱的 HTML 页面代码"           | `cloudapi2-frontend-component` | 生成完整驾驶舱接入页面                                                                                   |
| "接入航线编辑器组件代码"                     | `cloudapi2-frontend-component` | 生成 WaylineEditor 完整初始化代码                                                                        |
| "怎么获取帧级位置数据？"                     | `cloudapi2-sei-osd`            | 讲清 SEI vs OSD 差异，给出订阅代码                                                                       |
| "在 skeleton 里加一个设备状态订阅 feature"   | `cloudapi2-device-management`  | 生成 feature 模块骨架 + `@EventListener` 代码                                                            |
| "写代码创建一个自定义限飞区并同步到设备"     | `cloudapi2-map`                | 生成创建 → 同步 → 轮询同步状态的两段式代码                                                               |
| "写代码让喊话器播放一段 TTS 语音"            | `cloudapi2-payload`            | 生成含 DRC 建链前置的喊话器调用代码                                                                      |
| "写代码配置机载 AI 识别的目标过滤"           | `cloudapi2-ai`                 | 生成 AI 识别配置代码，按模块规则处理方法命名与参数体系                                                   |
| "SDK 返回 error_code: 4001 是什么意思？"     | `cloudapi2-troubleshooting`    | 走 4 阶段 RCA + 查错误码字典                                                                             |
| "让 AI Agent 帮我查一下所有在线设备"         | `cloudapi2-mcp-guide`          | 引导 AI 使用 `fh_device_list` MCP 工具                                                                   |
| "帮我把 MCP Server 部署到 10.66.x.x"         | `cloudapi2-mcp-deploy`         | 环境探测 + 逐步生成部署命令                                                                              |
| "帮我把 skeleton 部署到这台机器"             | `cloudapi2-skeleton-deploy`    | 三形态选型建议 + 逐步引导                                                                                |
| "把 https://xxx 文档加到知识库"              | `cloudapi2-knowledge-ingest`   | 模块归属分析 → 格式化 → 入库 + 索引重建                                                                  |
| "我要反馈一个问题" / "报个 bug" / "提个需求" | `cloudapi2-feedback`           | 结构化反馈：对话 → 采集 → 脱敏 → 确认 → 打包 → 上传网盘 → 创建 GitHub issue（GitHub 不可达时生成离线包） |

> **适合场景**：不确定参数怎么写、遇到报错需要排查、想理解某个 API 的含义时，直接对话效率最高。

---

#### 3.2 方式二：快捷指令

**当你已知所有参数时**，可直接输入快捷指令，Claude 立即生成对应的完整 HTML 代码，无需多轮对话。

**6 条可用指令：**

| 指令                       | 生成内容                                                     | 参数（按位置，均可省略）                                                     |
| -------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `/cloudapi2:wayline`       | 航线编辑器 / 航线预览完整 HTML（创建 / 编辑 / 预览三种模式） | mode（`create`/`edit`/`preview`）、serverUrl、waylineId（edit/preview 必填） |
| `/cloudapi2:cockpit`       | 驾驶舱完整 HTML                                              | frontHost、gatewaySn、droneSn                                                |
| `/cloudapi2:device`        | 设备管理完整 HTML                                            | frontHost、serverUrl                                                         |
| `/cloudapi2:device-window` | 设备小窗完整 HTML（并行监看多台设备）                        | frontHost、设备序列号（多个用逗号分隔）                                      |
| `/cloudapi2:multi-stream`  | 直播大屏完整 HTML（多路直播网格）                            | serverUrl、设备序列号（多个用逗号分隔）、gridCols（网格列数，默认 2）        |
| `/cloudapi2:replay`        | 飞行记录回放完整 HTML                                        | serverUrl、taskId                                                            |

---

**驾驶舱指令详细示例：**

```
/cloudapi2:cockpit http://xx.xx.xx.xx GW12345678 DV12345678
```

三个参数依次对应：

| 位置        | 示例值               | 含义                      |
| ----------- | -------------------- | ------------------------- |
| 第 1 个参数 | `http://xx.xx.xx.xx` | 前端服务地址（frontHost） |
| 第 2 个参数 | `GW12345678`         | 基站序列号（gatewaySn）   |
| 第 3 个参数 | `DV12345678`         | 无人机序列号（droneSn）   |

执行后，Claude 会输出一份**完整可运行的驾驶舱 HTML 页面**，以上参数已自动填入代码中，可直接使用。

**航线编辑器指令详细示例：**

`create` 模式（2 个参数，无需航线 ID）：

```
/cloudapi2:wayline create http://xx.xx.xx.xx:xxxxx/gateway
```

`edit` / `preview` 模式（3 个参数，第 3 个为航线 ID，必填）：

```
/cloudapi2:wayline edit http://xx.xx.xx.xx:xxxxx/gateway 510a56b9-4d6d-4f2e-8a1b-0c9d8e7f6a5b
```

参数依次对应：

| 位置        | 示例值                             | 含义                                                |
| ----------- | ---------------------------------- | --------------------------------------------------- |
| 第 1 个参数 | `create` / `edit` / `preview`      | 模式（创建 / 编辑 / 预览）                          |
| 第 2 个参数 | `http://xx.xx.xx.xx:xxxxx/gateway` | 后端网关地址（serverUrl）                           |
| 第 3 个参数 | `510a56b9-4d6d-...`                | 航线 ID（`edit` / `preview` 必填，`create` 不需要） |

> 不带参数直接输入 `/cloudapi2:wayline` 时，Claude 会先询问要使用哪种模式，再生成代码。

> **参数还没确认怎么办？**
> 直接输入 `/cloudapi2:cockpit`（不带任何参数），Claude 会用占位符生成模板，并标注需要您替换的位置。

> **适合场景**：参数已全部确认、需要快速拿到可用代码时，使用快捷指令效率最高。

---

#### 3.3 方式三：搭配 MCP Server 直接操控设备

**不再需要写代码**，让 AI Agent 直接调用 MCP 工具操控无人机 / 机场。

**示例对话（Claude Code 已配置 MCP Server）：**

> "帮我查一下工作空间下所有在线的机场"
> "把本地的 KMZ 航线导入工作空间，并在机场 GW12345678 上创建任务"
> "让无人机 DV12345678 起飞、飞到坐标 (113.9, 22.6)、然后返航"
> "订阅这架无人机的实时位置遥测 5 秒"

Claude 会通过 `cloudapi2-mcp-guide` Skill 判断该调用哪个 MCP 工具，编排多步调用链，返回结构化结果。

> **适合场景**：AI Agent 开发、无人机运维自动化、Prompt 调试演示。MCP Server 接入方式见 **第六章**。

## 第二部分：Skill 详解

---

### 第四章：Skill 清单

#### 4.1 13 个 Skill 一览

| Skill                          | 层级     | 方向          | 说明                                                                                                                                                                        |
| ------------------------------ | -------- | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cloudapi2-sdk-core`           | 水平基础 | 后端 Java SDK | 6 条核心规则 + 场景范本 + 代码模板，教 AI 写正确的 SDK 集成代码                                                                                                             |
| `cloudapi2-frontend-component` | 水平基础 | 前端组件      | 上云 API 2 7 大前端组件（航线编辑 / 航线预览 / 驾驶舱 / 设备小窗 / 设备管理 / 飞行记录回放 / 直播大屏）接入助手                                                             |
| `cloudapi2-mcp-guide`          | 水平基础 | MCP 工具路由  | 教 AI 在运行时选对 MCP Tool、编排多步调用（三问决策法）                                                                                                                     |
| `cloudapi2-device-management`  | 垂直场景 | 设备管理      | skeleton 后端项目扩展设备管理功能（OSD 订阅 / HMS 告警 / feature 模块创建），并覆盖机场控制、设备调试、日志、维修工单、设备自诊断、RTK 标定、网络测试等运维模块的 Java 调用 |
| `cloudapi2-sei-osd`            | 垂直场景 | SEI/OSD 遥测  | 帧级位置数据（SEI）+ 设备遥测（OSD）接入，含前端 Cesium 可视化                                                                                                              |
| `cloudapi2-map`                | 垂直场景 | 地图域        | 自定义飞行区、离线地图、解锁证书、地图元素的 SDK 接入，含"云端定义 ≠ 设备生效"的同步语义                                                                                    |
| `cloudapi2-payload`            | 垂直场景 | PSDK 负载域   | 探照灯、喊话器、PSDK Widget、浮窗、UI 资源接入，含喊话器音频直传                                                                                                            |
| `cloudapi2-ai`                 | 垂直场景 | AI 域         | AI Box 应用、机载 AI 识别与跟踪、AI 主动告警、AI Inside 算法生命周期、AI 目标检测告警接入                                                                                   |
| `cloudapi2-mcp-deploy`         | 垂直场景 | 部署引导      | 半自动引导将 MCP Server 部署到自有环境（SSE / stdio）                                                                                                                       |
| `cloudapi2-skeleton-deploy`    | 垂直场景 | 部署引导      | 半自动引导将 Skeleton 部署到自有环境（普通机器 / Docker Compose / K8s）                                                                                                     |
| `cloudapi2-knowledge-ingest`   | 横切     | 知识库入库    | 将外部文档自动收录到 knowledge/ 知识库并重建索引                                                                                                                            |
| `cloudapi2-troubleshooting`    | 横切     | 排障          | 本地采集 / 脱敏 / 判级 + 4 阶段 RCA + 错误码字典，必要时借助 MCP 与设备模拟器做实机验证                                                                                     |
| `cloudapi2-feedback`           | 横切     | 问题反馈      | 结构化反馈流程，自然语言反馈问题 / 需求 / 咨询等并提交 issue                                                                                                                |

> **层级说明**：水平基础层教通用规则（被垂直层引用）；垂直场景层教具体业务接入（引用水平层）；横切层不受场景限制，任何时候遇错/入库都可触发。
>
> **同一业务名词，两条路径**：地图、PSDK 负载、AI、设备运维等业务域，既能"写 Java 代码调用 SDK"，也能"让 AI 通过 MCP 直接执行"。要代码 → 对应的垂直 Skill；要直接操控 → `cloudapi2-mcp-guide`。

#### 4.3 SDK 集成 6 条核心规则

`cloudapi2-sdk-core` 内置以下 6 条硬约束，代码生成时会自动加入，AI 不会漏掉：

| 规则   | 说明                                                                               | 典型错误                                                                     |
| ------ | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 规则 1 | 先加载 JNI、注入鉴权头，再 `initialize()` 并检查返回值                             | 未注入鉴权头就初始化 → WebSocket 握手 401；未检查返回值 → 后续 API 返回 null |
| 规则 2 | 所有回调必须检查 `errorCode`                                                       | errorCode 非 SUCCESS 时直接使用 data → NPE                                   |
| 规则 3 | `listenId` 必须保存，关闭时 `cancel`                                               | 不保存 listenId → 回调泄漏                                                   |
| 规则 4 | 飞控指令必须先抢权、用完释放                                                       | 未 acquire 就发指令 → 权限错误                                               |
| 规则 5 | `getDroneInstance` / `getDockInstance` / 模块 getter 可能返回 null，必须 null 防御 | 不做 null 检查 → NPE                                                         |
| 规则 6 | 危险操作必须先输出风险警告                                                         | 生成 `takeoff` / 紧急停机代码时未提醒用户确认 → 误操作                       |

### 第五章：MCP Server 是什么

DJI Cloud API 2 MCP Server 是一个符合 [MCP 规范](https://modelcontextprotocol.io/) 的中间服务，将 DJI Cloud API 2 PaaS SDK 的能力（设备管理、飞行控制、媒体管理、航线任务、空域安全、相机与负载等）暴露为 AI 工具可调用的标准接口，共 **67 个 `fh_*` 工具**。

简单来说：**配置完成后，你可以用自然语言让 AI 帮你操控无人机和机场。**

```
┌─────────────────────┐         JSON-RPC          ┌──────────────────────────────┐
│   AI Agent / LLM    │ ◀────────────────────────▶ │  DJI Cloud API 2 MCP Server  │
│    (Claude Code)    │   stdio 或 SSE transport   │  (Spring Boot, Java 17)      │
└─────────────────────┘                            └───────────────┬──────────────┘
                                                                   │  JNI / SDK
                                                   ┌───────────────▼──────────────┐
                                                   │  DJI Cloud API 2 PaaS SDK    │
                                                   │  (Linux x86_64 / aarch64)    │
                                                   └───────────────┬──────────────┘
                                                                   │  HTTPS/WebSocket
                                                   ┌───────────────▼──────────────┐
                                                   │  DJI Cloud API 2 云端平台    │
                                                   └───────────────┬──────────────┘
                                                                   │  4G/5G/RC
                                                   ┌───────────────▼──────────────┐
                                                   │  无人机 + 机场（Dock）       │
                                                   └──────────────────────────────┘
```

**典型场景：**

- **AI 辅助巡检调度**：用自然语言描述巡检路线，Agent 自动生成航线并执行飞行任务
- **无人机状态监控**：AI 持续查询设备遥测，异常时自动触发告警或返航
- **开发调试加速**：开发者在 Claude Code 中直接对话 DJI Cloud API 2，无需切换控制台

#### 6.2 接入 Claude Code

##### 获取 token 的方式：

在部署了 MCP Server 的服务端执行：

```bash
sudo docker inspect pf-devkit-mcp --format '{{range .Config.Env}}{{println .}}{{end}}' | grep '^FH_SSE_AUTH_TOKEN=' | cut -d= -f2-
```

##### 接入 claude code

> **安全提示：** MCP Server 的默认 token 必须在接入前修改，避免默认凭据泄露带来安全风险。

**1. 修改 MCP Server token（必做）：**

```bash
# 生成新 token
openssl rand -hex 32

# 修改 MCP Server 容器的环境变量 FH_SSE_AUTH_TOKEN 为生成的新 token，然后重启容器
```

**2. 在终端执行接入命令：**

```bash
claude mcp add dji-cloud-api2 http://<ip>:30812/pf-devkit/ai-plugin/mcp/sse --transport sse -s user -H "Authorization: Bearer <token>"
```

> 生产环境建议使用 `https://` 协议，避免 token 经明文 HTTP 传输被截获。

卸载 MCP 的命令：

```bash
claude mcp remove dji-cloud-api2
```

#### 7.1 基本使用流程

所有操作遵循以下基本流程（未调用 `fh_connect` 时，其他工具都会返回 "No active session"）：

```
1. 建立会话      fh_connect（所有操作的前提，必须第一步）
       │
2. 查询设备      fh_device_list → 获取设备 SN
       │
3. 获取状态      fh_drone_snapshot / fh_dock_snapshot
       │
4. 执行操作      飞行控制 / 航线任务 / 媒体管理 / ...
       │
5. 释放资源      fh_control_release（如有获取控制权）
```

#### 7.2 飞行操作的前置条件链

如果你需要实时控制无人机飞行（指点飞行、环绕飞行等），需要按以下顺序建立前置条件：

```
fh_connect                → 建立会话
  └── fh_control_acquire  → 获取飞行控制权（互斥资源）
        └── fh_drc_connect → 建立 DRC 低延迟链路
              └── fh_takeoff / fh_flyto / fh_poi ...  → 执行飞行指令
              └── fh_drc_disconnect → 断开 DRC
        └── fh_control_release → 释放控制权（必须！即使出错也要释放）
```

> 不用担心记不住这个链路——AI 会自动按正确顺序调用。你只需要用自然语言描述你想做什么。

### 第九章：安全机制

MCP Server 内置 4 级安全等级，防止 AI 误操作真实设备。

> **使用前请注意**：正式使用前，请自行评估并补充安全措施：
>
> - 本章第 9.3 节中的"无人工确认"类写操作，不会弹窗，仅受安全等级限制，需自行补充确认，或在网关层拒绝对应调用。
> - 模拟器工具 `sim_*` 常驻注册，不使用模拟器时，建议在网关或网络层拒绝对应调用。
> - 目前一个 MCP Server 实例只对应一个工作空间，且只维护一个活跃会话，多客户端并发连接会共享同一个 SDK 实例。
> - 传输使用 HTTPS，并妥善保管 `FH_SSE_AUTH_TOKEN` 与 `FH_OPERATOR_TOKEN`。

#### 9.1 SecurityLevel 分级

| 等级   | 名称              | 举例                                                                          | 默认允许                             |
| ------ | ----------------- | ----------------------------------------------------------------------------- | ------------------------------------ |
| **L0** | 只读              | `fh_device_list` / `fh_drone_snapshot` / `fh_wayline_status`                  | ✅ 是                                 |
| **L1** | 可逆操作          | `fh_wayline_upload` / `fh_dock_control` / `fh_control_release`                | ✅ 是                                 |
| **L2** | 飞行操作          | `fh_control_acquire` / `fh_drc_connect` / `fh_takeoff` / `fh_wayline_execute` | ✅ 是（需控制权、DRC 链路与人工确认） |
| **L3** | 紧急 / 高危不可逆 | `fh_emergency_stop` / `fh_ops` 的 shutdown 动作                               | ⚠️ 需显式提升                         |

> **混合等级工具**：部分工具的不同动作等级不同，例如 `fh_flight_task` 的 `create` / `edit` 为 L1，`execute` / `delete` 为 L2；`fh_ops` 的健康检查为 L0、调整日志级别为 L1、shutdown 为 L3。以各工具动作级声明为准。

#### 9.2 安全等级上限

平台管理员可通过 `FH_MAX_SECURITY_LEVEL` 环境变量设置全局上限，**默认值为 `2`**：

- 设为 `1`：只允许读取和可逆操作，所有飞行指令被拒绝
- 设为 `2`（默认，生产环境推荐）：允许飞行操作（起飞、指点、环绕、返航、执行航线），禁止紧急停止
- 设为 `3`：允许所有操作（仅限紧急场景）

超出上限的调用会被直接拒绝，返回 `ERR_SECURITY_LEVEL`。

> **启用 L3 的完整前置条件**：除了把 `FH_MAX_SECURITY_LEVEL` 设为 `3`，还必须配置 `FH_OPERATOR_TOKEN`（用 `openssl rand -hex 32` 生成），并在调用急停时由真人提供对应的 `operator_token`。该 Token 未配置时，L3 操作一律拒绝。

##### 获取安全等级的方式：

在部署了 MCP Server 的服务端执行：

```bash
sudo docker inspect pf-devkit-mcp --format '{{range .Config.Env}}{{println .}}{{end}}' | grep '^FH_MAX_SECURITY_LEVEL=' | cut -d= -f2-
```

**配置方式：** 修改容器的环境变量

```bash
FH_MAX_SECURITY_LEVEL=2      # 生产建议：只放开到 L2，禁止紧急停机
FH_MAX_SECURITY_LEVEL=3      # 演示 / 开发：允许全部工具（还需配置 FH_OPERATOR_TOKEN）
```

#### 9.3 人工确认（MCP Elicitation）

支持 MCP Elicitation 协议的客户端（如 Claude Code）在执行**声明了人工确认**的操作时，Server 会**主动向用户弹窗确认**，而不依赖 AI 自动传入 `confirm=true`。

**是否弹窗取决于工具自身的声明，与安全等级高低无关**，分为三类：

| 类别           | 行为                               | 典型工具                                                                                                                                                                                                    |
| -------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **类级确认**   | 该工具的所有调用都弹窗             | `fh_takeoff` / `fh_flyto` / `fh_return_home` / `fh_poi` / `fh_emergency_stop` / `fh_wayline_execute` / `fh_wayline_control` / `fh_control_acquire` / `fh_drc_connect` / `fh_media_delete`                   |
| **动作级确认** | 仅高危动作弹窗，低危动作不弹       | `fh_flight_task` / `fh_workspace` / `fh_firmware` / `fh_dock_control` / `fh_ops` 等                                                                                                                         |
| **无人工确认** | 不弹窗，仅受安全等级与前置条件限制 | `fh_control_release` / `fh_drc_disconnect` / `fh_payload_acquire` / `fh_payload_release` / `fh_live_sync` / `fh_psdk_widget` / `fh_maintenance` / `fh_diagnosis` / `fh_camera`（拍照、录像等动作）、`sim_*` |

不支持 Elicitation 的客户端（如无弹窗能力的 HTTP 调用方）可通过 `confirm=true` 参数作为回退路径，该回退仅适用于 L1 / L2；L3 急停必须额外提供 `operator_token`。

> 实际是否弹窗，以连接后 `tools/list` 返回的工具描述为准。

#### 9.4 dry_run 预览模式

**写入类工具**（如 `fh_takeoff`、`fh_flyto`、`fh_return_home`、`fh_poi`、`fh_wayline_execute`、`fh_dock_control`、`fh_flight_area_manage`、`fh_media_delete`）支持 `dry_run=true` 参数。具体某个工具是否支持，以其 `inputSchema` 中是否存在 `dry_run` 属性为准。当使用 dry_run 时：

- 参数校验和前置条件检查正常执行
- **不会实际调用 SDK 或执行飞行操作**
- 返回"如果真正执行会做什么"的预览信息

**适用场景：**

- 首次使用时验证参数是否正确
- 演示操作流程但不实际执行
- 教学和培训场景

**使用方式：** 告诉 AI "用 dry_run 模式预览一下" 或 "不要真的执行，先给我看看会怎样"。

> 例外：`fh_ops` 的 shutdown 走独立的 L3 人工确认流程，不提供 `dry_run` 预览。

### 第十一章：常见问题

#### 11.1 Plugin 安装与使用

**Q：**`claude plugin marketplace add` **报错 "command not found"？**

您的 Claude Code 版本可能低于 v1.0，请升级 Claude Code。

**Q：Plugin 安装后 Skill 没触发怎么办？**

1. 确认 `/plugins` 输出中 `cloudapi2@dji` 状态为 **enabled**
2. 确认 JSON 格式正确 —— 运行 `cat ~/.claude/settings.json | python3 -m json.tool` 验证
3. **新开一个 Claude Code 会话**（旧会话不生效）

**Q：Skill 生成的代码质量怎么样？**

`cloudapi2-sdk-core` 内置了资深开发工程师截止目前已积累的 6 条硬约束（详见 [4.3](#_4-3-sdk-集成-6-条核心规则)）：

1. 先加载 JNI、注入鉴权头，再 `initialize()` 并检查返回值
2. 所有回调必须检查 `errorCode`
3. 所有 `listen*` 必须保存 `listenId`，并配 `cancelListen*`
4. 飞控指令必须先获取控制权，用完释放
5. `getDroneInstance` / `getDockInstance` / 模块 getter 返回值必须 null 防御
6. 危险操作（起飞、返航、急停等）必须先输出风险警告

代码生成时这些约束会自动加入，AI 不会漏掉。

---

#### 11.2 MCP 使用

**Q：MCP 连接失败，提示 "401 Unauthorized"**

MCP Token 无效或已过期。请重新获取 Token 并更新配置。

**Q：连接成功但调用工具时提示 "No active session"**

会话可能已超时断开（默认 30 分钟无操作，由 `FH_SESSION_TIMEOUT` 控制）。重新发送"连接 DJI Cloud API 2"即可恢复。

**Q：操作被拒绝，提示 "insufficient security level"**

你尝试执行的操作超过了平台管理员设置的安全等级上限（返回 `ERR_SECURITY_LEVEL`）。请联系管理员调整 `FH_MAX_SECURITY_LEVEL` 或改用低等级操作。

**Q：飞行指令失败，提示 "Flight control authority not acquired" 或 "No control authority"**

飞行操作前需要先通过 `fh_control_acquire` 获取控制权。正常情况下 AI 会自动处理，如果仍然失败，可能是其他 session 持有控制权，等待对方释放或联系管理员。

**Q：无人机显示 offline，无法操作**

机场内的无人机在待机时通常是离线状态（断电存储），这是正常现象。只要**机场（Airport/Dock）在线**即可执行起飞等操作。

**Q：如何在不实际飞行的情况下测试？**

使用 **dry_run 模式**——写入类工具支持 `dry_run=true`，只校验不执行（见 [9.4](#_9-4-dry-run-预览模式)）。也可以搭配[设备模拟器](./04.simulator.md)，用 `sim_*` 工具在虚拟设备上联调。

**Q：操作执行后无人机没反应**

请检查：

1. 设备是否在线（`fh_device_list`）
2. 是否已建立 DRC 链路（`fh_session_info` 查看链路状态）
3. 无人机是否在机场内（需要先起飞）
4. 信号是否正常（查看 OSD 中的 GPS 和链路质量）

**Q：如何查看操作历史？**

使用 `fh_flight_record` 查询飞行记录，或使用 `fh_hms` 查询健康告警历史。工具调用的审计日志由 MCP Server 记录。

**Q：支持同时控制多台无人机吗？**

当前 MCP Server 只维护一个活跃会话，且会话同一时间只持有一台设备的控制权（控制权互斥）。可在释放控制权后切换到另一台。查询和监控操作不受此限制，可同时查看多台设备状态。一个 MCP Server 实例对应一个工作空间，多工作空间需运行多个实例。

### 第十二章：前端组件错误码速查

以下为前端组件抛出的错误码。**同一个数字码在不同组件中含义不同，不能跨组件套用**，查询前请先确认是哪个组件报错。

| 错误码 | 组件                           | 含义                       | 常见排查方向                                                                                               |
| ------ | ------------------------------ | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `4001` | 航线编辑                       | WebSocket 鉴权失败         | 检查 token 是否过期、`auth.headers` 回调是否每次返回最新 token                                             |
| `4002` | 航线编辑                       | WebSocket 连接断开         | 检查网络、`wssUrl` 路径与协议（HTTPS 页面用 wss://）                                                       |
| `5000` | 航线编辑 / 航线预览 / 飞行记录 | API 请求失败               | 检查 `serverUrl`、浏览器控制台是否有跨域报错、服务端日志                                                   |
| `5001` | 航线编辑 / 航线预览 / 飞行记录 | API 鉴权失败（401 / 403）  | 检查 token、账号对目标工作空间的权限                                                                       |
| `6000` | 航线编辑 / 飞行记录            | 航线数据解析失败           | 检查 KMZ 格式是否合法                                                                                      |
| `6000` | 航线预览                       | 航线 KMZ 下载失败          | 检查下载地址在当前网段是否可达                                                                             |
| `6001` | 航线编辑                       | WASM 模块加载失败          | 检查前端资源路径、跨域与 MIME 配置                                                                         |
| `6001` | 航线预览                       | 航线 KMZ 解析失败          | 检查 KMZ 文件是否完整                                                                                      |
| `6002` | 航线编辑 / 飞行记录            | 地图初始化失败             | 检查 Cesium 资源、WebGL 是否可用、`loadMap()` 是否先于 `render()` / `mount()` 调用、DOM 容器是否存在且可见 |
| `6002` | 航线预览                       | 运行时依赖（WASM）加载失败 | 检查前端资源路径、跨域与 MIME 配置                                                                         |
| `6003` | 航线预览                       | 地图初始化失败             | 检查 `Cesium.js` 是否同步加载、WebGL 是否可用                                                              |
| `7000` | 航线编辑                       | OSS 上传失败               | 检查 OSS 凭证、网络与文件大小限制                                                                          |

> 直播大屏使用独立的字符串错误码（如 `NOT_INITIALIZED`，表示未调用 `initLivePlayer()`），设备小窗没有错误码。
>
> 设备端的 6 位错误码请查阅[错误码](./14.error-codes.md)；SDK 与平台接口的错误码，可交给 `cloudapi2-troubleshooting` 查询。

> **触发** `cloudapi2-troubleshooting` **Skill 直接问：** "error_code 4001 怎么排查？" —— Claude 会自动走 4 阶段 RCA（Reproduce → Locate → [实机验证] → Fix → Verify）+ 查错误码字典给出定位。

| **gatewaySn / droneSn**      | 基站（机场 / 网关）序列号 / 无人机序列号，前端组件与飞控接口的关键入参                                          |
