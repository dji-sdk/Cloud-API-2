# 使用上云 API 2 二次开发 Demo

> 为了帮助开发者更快上手上云 API 2，上云 API 2 为开发者提供了二次开发 Demo - 上云 API 2 无人机管理平台。

:::warning
上云 API 2 无人机管理平台是为帮助开发者快速理解并上手上云 API 2 而提供的 Demo 应用，不能直接作为生产级系统使用。
:::

本文档说明如何将上云 API 2 无人机管理平台（Spring Boot 后端 + Vue 3 前端 + MySQL）部署到自有环境。**交付形态为源码，需要由开发者自行构建与运行**。

> 访问 [DJI 上云 API 2 官方 GitHub 仓库](https://github.com/dji-sdk/Cloud-API-2)获取 Demo 源码。

上云 API 2 开发 Demo（下文简称 skeleton）支持三种部署形态，按规模自选：
> | 形态 | 适用场景 | 复杂度 | 前置依赖 |
> |------|----------|--------|----------|
> | 普通机器 | 单机/小规模，已有物理机或虚拟机 | 中 | JDK17、MySQL8、nginx、systemd |
> | Docker Compose | 单机容器化，便于迁移与版本管理 | 低 | Docker 24+、Docker Compose v2 |
> | Kubernetes | 生产级高可用、多副本、弹性伸缩 | 高 | K8s 集群、镜像仓库 |
>
> **推荐路径**：安装部署 AI Plugin 后基于 AI 引导完成，无需逐节阅读。


## 1. 概览

### 1.1 架构

```
                    ┌──────────────┐
   用户 ──80/443──▶ │  fh-ui       │  Nginx + Vue 3 dist（端口 80）
                    └──────┬───────┘
                           │ /pf-devkit/ai-plugin/skeleton/* → proxy
                           ▼
                    ┌──────────────┐
                    │  skeleton    │  Spring Boot（端口 8080，context-path=/pf-devkit/ai-plugin/skeleton）
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼                         ▼
        ┌──────────┐            ┌──────────────┐
        │  mysql   │            │  MCP Server  │（独立部署，Chat 启用时需要）
        └──────────┘            └──────────────┘
```

| 组件 | 端口（容器内） | 说明 |
|------|----------------|------|
| `fh-ui` | 80 | 前端 Nginx，托管 Vue 3 静态资源，反代后端 API |
| `skeleton` | 8080 | 后端 Spring Boot，context-path `/pf-devkit/ai-plugin/skeleton` |
| `mysql` | 3306 | MySQL 8.0，用户模块持久化 |
| `MCP Server` | 8080 | 独立部署，Chat 功能依赖（可选） |

### 1.2 平台限制

- **SDK JNI 原生库仅支持 Linux x86_64（amd64）**。后端需运行在 amd64 平台（Docker/K8s 均要求，普通机器要求 Linux x86_64）。
- macOS/Windows 仅能运行 **mock** 模式（不加载原生库），用于本地开发/演示。

### 1.3 外部依赖

| 依赖 | 必需 | 说明 |
|------|------|------|
| MySQL 8.0+ | 是 | 用户模块持久化（`t_user` 表） |
| FlightHub PaaS（SDK） | sdk profile 必需 | `FH_SKELETON_SDK_*` 连接参数 |
| MCP Server | 否（Chat 启用时是） | `FH_CHAT_MCP_URL` 指向 |
| Spring AI Provider | 否 | Chat 功能用，不配则 Chat 不可用 |

## 4. 手动部署

> 以下按三种部署形态分节说明。选择适合你环境的形态，跳过其余。

### 4.1 普通机器（JDK + MySQL + nginx + systemd）

> 适用：单台 Linux x86_64 物理机/虚拟机。无需 Docker。

#### 安装私有 SDK JAR（构建机一次性操作）

`libs/flight-hub-sdk-3.1.1.jar` 不在任何远端仓库，在构建机上首次 Maven 编译前需手动安装到本地仓库：

```bash
mvn install:install-file \
  -Dfile=libs/flight-hub-sdk-3.1.1.jar \
  -DgroupId=com.dji.flighthubsdk \
  -DartifactId=flight-hub-sdk \
  -Dversion=3.1.1 \
  -Dpackaging=jar
```

> Docker/K8s 部署无需此步——Dockerfile 多阶段构建已内置 JAR 安装。

#### 安装运行时与依赖

```bash
# JDK 17
sudo apt update && sudo apt install -y openjdk-17-jre-headless

# MySQL 8
sudo apt install -y mysql-server
sudo systemctl enable --now mysql

# nginx
sudo apt install -y nginx

# 构建与解压依赖
sudo apt install -y unzip curl

# 后端 JNI 原生库系统依赖
sudo apt install -y libatomic1 libgl1 libegl1 libx11-6 libxcomposite1 \
  libxdamage1 libxext6 libxfixes3 libxi6 libxrandr2 libxrender1 libxtst6
# Ubuntu 22.04+ 额外需要 focal 源安装 libssl1.1（SDK 依赖）：
sudo sh -c 'echo "deb http://archive.ubuntu.com/ubuntu focal-updates main" > /etc/apt/sources.list.d/focal.list'
sudo apt update && sudo apt install -y libssl1.1
sudo rm -f /etc/apt/sources.list.d/focal.list
```

#### 构建

**Maven Profile**：生产部署**必须** `-Psdk-real`，否则打包的是 mock 实现。

```bash
# 后端
cd skeleton
mvn clean package -Psdk-real -DskipTests
# 产物：app/fh-skeleton-app/target/fh-skeleton-app-0.1.0-SNAPSHOT.jar

# 前端
cd skeleton/web
npm ci && npm run build
# 产物：web/dist/
```

#### 生成密钥与密码

```bash
openssl rand -hex 32   # JWT 签名密钥（必填，至少 32 字节）
openssl rand -hex 24   # MySQL 数据库密码
```

#### 初始化数据库

```bash
sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS fh_skeleton DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'fh_skeleton'@'localhost' IDENTIFIED BY '<db-password>';
GRANT ALL PRIVILEGES ON fh_skeleton.* TO 'fh_skeleton'@'localhost';
FLUSH PRIVILEGES;
SQL
```

> 首次启动后 JPA `ddl-auto=update` 会自动建表。生产建议改用 `validate` + 迁移脚本管理 schema。

#### 部署后端

```bash
sudo mkdir -p /opt/fh-skeleton
sudo cp app/fh-skeleton-app/target/fh-skeleton-app-0.1.0-SNAPSHOT.jar /opt/fh-skeleton/

# 解压 SDK native lib
sudo bash skeleton/deploy/native-lib-extract.sh /opt/fh-skeleton/fh-skeleton-app-0.1.0-SNAPSHOT.jar

# 创建低权限运行用户
sudo useradd -r -s /sbin/nologin fhskeleton || true
sudo chown -R fhskeleton:fhskeleton /opt/fh-skeleton
```

#### 配置环境变量并注册 systemd

```bash
sudo cp skeleton/deploy/skeleton.env.example /etc/fh-skeleton.env
sudo chown root:root /etc/fh-skeleton.env && sudo chmod 600 /etc/fh-skeleton.env
# 编辑 /etc/fh-skeleton.env：必填 FH_JWT_SECRET、FH_DB_*；sdk 模式另需 FH_SKELETON_SDK_*
sudo vi /etc/fh-skeleton.env

sudo cp skeleton/deploy/skeleton.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now skeleton
```

#### 部署前端并配置 nginx

```bash
sudo mkdir -p /usr/share/nginx/html/skeleton-ui
sudo cp -r web/dist/* /usr/share/nginx/html/skeleton-ui/

# 前端运行时配置
sudo tee /usr/share/nginx/html/skeleton-ui/config.js >/dev/null <<'EOF'
window.__FH_CONFIG__ = {
  FH2_ADDRESS: '<your-fh2-address>',
  FH2_PORT: '30812',
  FH2_WSS_URL: '<your-fh2-wss-url>',
  FH2_PRJ_ID: '<your-prj-id>',
  DEFAULT_THEME: 'light',
  PRIMARY_COLOR: '#1a73e8',
  PRIMARY_HOVER_COLOR: '',
  MOCK_ENABLED: 'false',
  MAP_PROVIDER: 'esri',
  BING_KEY: '',
  TIANDITU_KEY: '',
};
EOF

sudo cp skeleton/deploy/skeleton-ui.conf /etc/nginx/conf.d/skeleton-ui.conf
sudo nginx -t && sudo systemctl reload nginx
```

#### 验证

```bash
curl -f http://127.0.0.1:8080/pf-devkit/ai-plugin/skeleton/actuator/health
# {"status":"UP"}
curl -f http://127.0.0.1/
journalctl -u skeleton -f
```

### 4.2 Docker Compose

> 适用：单机容器化，首选推荐，镜像由您自行构建。

#### 构建并推送镜像

```bash
cd <repo-root>
# 后端（多阶段构建，内含 Maven 编译 + SDK JAR 安装 + native lib 解压）
docker build -f skeleton/docker/Dockerfile -t <REGISTRY>/paas-sdk-devkit/skeleton:<TAG> .
# 前端
docker build -f skeleton/web/Dockerfile -t <REGISTRY>/paas-sdk-devkit/skeleton-ui:<TAG> skeleton/
# 推送
docker push <REGISTRY>/paas-sdk-devkit/skeleton:<TAG>
docker push <REGISTRY>/paas-sdk-devkit/skeleton-ui:<TAG>
```

> **平台**：后端镜像需 `--platform linux/amd64`（SDK native lib 仅 amd64）。Apple Silicon 加 `DOCKER_DEFAULT_PLATFORM=linux/amd64`。

#### 配置 .env

```bash
cd skeleton
cp deploy.env.example deploy.env
# 编辑 deploy.env，必填项：
#   REGISTRY=<your-registry>
#   MYSQL_ROOT_PASSWORD / FH_DB_PASSWORD（openssl rand -hex 24）
#   FH_JWT_SECRET（openssl rand -hex 32）
#   FH_CHAT_MCP_URL（MCP Server 地址，见 **MCP Server 部署** 章节）
#   FH_PROFILE=sdk + FH_SKELETON_SDK_*（生产）
#   VITE_FH2_*（前端 FH2 配置）
```

#### 启动

```bash
# 方式 A：本地构建运行
docker compose -f skeleton/docker/docker-compose.yml --env-file skeleton/deploy.env up --build

# 方式 B：远端部署脚本（SSH + 拉镜像）
./skeleton/deploy.sh
```

#### 验证

```bash
curl http://<server-ip>:<BACKEND_PORT>/pf-devkit/ai-plugin/skeleton/actuator/health
# {"status":"UP"}
```

#### 快速开始（本地 mock）

零配置本地启动（mock 模式，无需真 SDK）：

```bash
cd skeleton/docker
docker compose up --build
# 验证
curl http://localhost:8080/pf-devkit/ai-plugin/skeleton/actuator/health
curl http://localhost:8080/pf-devkit/ai-plugin/skeleton/api/v1/devices
# 停止
docker compose down
```

### 4.3 Kubernetes

> 适用：生产级高可用、多副本、弹性伸缩。Manifest 位于 `skeleton/deploy/k8s/`。

#### 准备镜像

构建方式与 Docker Compose 相同（见 **Docker Compose** 章节），推送到集群可拉取的私有仓库。

#### 编辑 Secret 与 ConfigMap

```bash
cd skeleton/deploy/k8s

# ① MySQL 密码
vi 01-mysql-secret.yaml

# ② 后端
vi 04-backend-secret.yaml    # FH_JWT_SECRET、FH_DB_PASSWORD、FH_SKELETON_SDK_TOKEN
vi 03-backend-configmap.yaml  # FH_SKELETON_SDK_ADDRESS、FH_CHAT_MCP_URL 等

# ③ 前端
vi 06-frontend-configmap.yaml  # VITE_FH2_ADDRESS、VITE_FH2_WSS_URL

# ④ 镜像名
vi 05-backend-deploy.yaml 07-frontend-deploy.yaml
```

#### 应用

```bash
kubectl apply -f 00-namespace.yaml
kubectl apply -f 01-mysql-secret.yaml
kubectl apply -f 02-mysql-sts.yaml
kubectl apply -f 03-backend-configmap.yaml
kubectl apply -f 04-backend-secret.yaml
kubectl apply -f 05-backend-deploy.yaml
kubectl apply -f 06-frontend-configmap.yaml
kubectl apply -f 07-frontend-deploy.yaml
kubectl apply -f 08-ingress.yaml
```

#### 验证

```bash
kubectl -n fh-skeleton get pods,svc,ingress
kubectl -n fh-skeleton port-forward svc/skeleton-backend 8080:8080 &
curl -f http://127.0.0.1:8080/pf-devkit/ai-plugin/skeleton/actuator/health
```

#### TLS 与域名（可选）

编辑 `08-ingress.yaml`，将 `tls:` 块取消注释并填充 `tls-secret`，`host` 替换为实际域名。

#### 滚动升级与回滚

```bash
# 升级
kubectl -n fh-skeleton set image deployment/skeleton-backend skeleton=<REGISTRY>/...:<NEW_TAG>
kubectl -n fh-skeleton set image deployment/skeleton-frontend nginx=<REGISTRY>/...:<NEW_TAG>
kubectl -n fh-skeleton rollout status deployment/skeleton-backend

# 回滚
kubectl -n fh-skeleton rollout undo deployment/skeleton-backend
kubectl -n fh-skeleton rollout undo deployment/skeleton-frontend
```

## 5. MCP Server 部署（Chat 功能依赖，可选）

### 5.1 为什么需要

skeleton 的 AI ChatBot 通过 MCP（Model Context Protocol）调用 FlightHub 工具能力。启用 Chat 时，`FH_CHAT_MCP_URL` 必须指向一个已部署的 MCP Server。MCP Server 独立部署（不随 skeleton compose 栈启动）。

### 5.2 Docker 形态

```bash
cd mcp
cp .env.example .env
# 编辑 .env：必填 FH_SERVER_ADDRESS / FH_ACCESS_TOKEN / FH_WORKSPACE_UUID / FH_SSE_AUTH_TOKEN
#   FH_SSE_AUTH_TOKEN 生成：openssl rand -hex 32
#   FH_MAX_SECURITY_LEVEL 生产建议 2（允许飞行控制，禁止 L3 紧急停机）
REGISTRY=<your-registry> docker compose up -d
```

验证：`curl -f http://<mcp-host>:8080/pf-devkit/ai-plugin/mcp/health`

### 5.3 K8s 形态

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: fh-mcp
  namespace: fh-skeleton
spec:
  replicas: 1
  selector:
    matchLabels:
      app: fh-mcp
  template:
    metadata:
      labels:
        app: fh-mcp
    spec:
      nodeSelector:
        kubernetes.io/arch: amd64
      containers:
        - name: mcp
          image: <REGISTRY>/paas-sdk-devkit/mcp:<TAG>
          ports:
            - containerPort: 8080
          env:
            - name: FH_TRANSPORT
              value: "sse"
            - name: FH_SSE_PORT
              value: "8080"
            - name: FH_SSE_AUTH_TOKEN
              value: "<MCP_SSE_AUTH_TOKEN>"
            - name: FH_SERVER_ADDRESS
              value: "<FLIGHTHUB_SERVER_ADDRESS>"
            - name: FH_SERVER_PORT
              value: "443"
            - name: FH_ACCESS_TOKEN
              value: "<FLIGHTHUB_ACCESS_TOKEN>"
            - name: FH_WORKSPACE_UUID
              value: "<FLIGHTHUB_WORKSPACE_UUID>"
            - name: FH_MAX_SECURITY_LEVEL
              value: "2"
            - name: GLIBC_TUNABLES
              value: "glibc.rtld.execstack=2"
          resources:
            requests: { cpu: 100m, memory: 512Mi }
            limits: { cpu: "1", memory: 1Gi }
---
apiVersion: v1
kind: Service
metadata:
  name: fh-mcp
  namespace: fh-skeleton
spec:
  selector:
    app: fh-mcp
  ports:
    - port: 8080
      targetPort: 8080
```

> `GLIBC_TUNABLES=glibc.rtld.execstack=2` 解决 glibc 2.39+ 拒绝 execstack .so 的问题。生产 Secret 化敏感变量。

### 5.4 与 skeleton 联调

| skeleton 变量 | 值 |
|---|---|
| `FH_CHAT_MCP_URL` | `http://<mcp-service>:8080`（K8s 用 `http://fh-mcp:8080`） |
| `FH_CHAT_MCP_AUTH_TOKEN` | 与 MCP Server 的 `FH_SSE_AUTH_TOKEN` 一致 |
| `FH_CHAT_ENABLED` | `true` |

启用 Chat 后需同时配置 Spring AI Provider API Key（`SPRING_AI_OPENAI_API_KEY` 等）。

## 7. 升级与回滚

### 7.1 普通机器

```bash
# 升级
sudo systemctl stop skeleton
sudo cp -r web/dist/* /usr/share/nginx/html/skeleton-ui/
sudo cp app/fh-skeleton-app/target/fh-skeleton-app-*.jar /opt/fh-skeleton/
sudo bash skeleton/deploy/native-lib-extract.sh /opt/fh-skeleton/fh-skeleton-app-*.jar
sudo systemctl start skeleton

# 回滚：保留旧 jar 时直接换回；无历史版本时用 git 检出旧 tag 重新构建
```

## 8. 常见问题与故障排查

### 8.1 常见问题

| 问题 | 排查 |
|------|------|
| 启动失败：JWT 未配置 | `FH_JWT_SECRET` 必填（至少 32 字节）。`openssl rand -hex 32` |
| 启动失败：SDK initialize | sdk profile 下 `FH_SKELETON_SDK_TOKEN/ADDRESS/NOTIFICATION_SERVER` 是否完整；构建是否用了 `-Psdk-real` |
| `.so` 加载失败 | native lib 系统依赖缺失（`libssl1.1` 等）；非 amd64 平台 |
| 设备不出现 | mock 模式等 3-4s 自动上线；sdk 模式查日志 |
| Chat 不可用 | `FH_CHAT_ENABLED=true`？`FH_CHAT_MCP_URL` 可达？API Key 配置？ |
| 前端地图不显示 | `VITE_MAP_PROVIDER` 与 key 不匹配（bing/tianditu 需 key） |
| 前端 404 | 静态产物未部署或路径不对（SPA fallback 未生效） |
| SSE 被 nginx buffer | 反代需 `proxy_buffering off` + 300s 超时 |
| docker build 很慢 | 首次需 mvn 下载依赖（~10min），后续利用 layer cache |
| 镜像太大（~700MB） | SDK native lib 占 404MB，无法压缩 |
| macOS ARM64 platform 错误 | docker-compose.yml 加 `platform: linux/amd64` |

### 8.2 故障排查

**日志查看**：

```bash
# 普通机器
journalctl -u skeleton -f
# Docker
docker logs pf-devkit-skeleton-server --tail 100
# K8s
kubectl -n fh-skeleton logs deployment/skeleton-backend --tail 100
```

**健康检查端点**：

| 端点 | 认证 | 响应 |
|------|------|------|
| `GET /pf-devkit/ai-plugin/skeleton/actuator/health` | 否 | `{"status":"UP"}` |
| `GET /pf-devkit/ai-plugin/skeleton/actuator/info` | 否 | 应用信息 |

**故障定位**：

| 现象 | 定位 |
|------|------|
| 后端起不来 | 先查 JWT（必填）→ 再查 DB 连通 → 再查 SDK 凭据 |
| 健康检查超时 | SDK native lib 加载慢，放大 `initialDelaySeconds`/`start_period` |
| MySQL 初始化脚本没执行 | 数据卷已有数据时 `/docker-entrypoint-initdb.d/` 不执行；清空卷后重启 |

## 9. 清理部署（卸载）

> 清理 = 停止服务 + 移除运行态资源 + **按需**删除数据。三形态命令互不影响，按实际部署形态选择。
> **危险操作确认原则**：删除数据（数据卷 / PVC / 数据库）、删除镜像、删除 systemd unit 与配置目录均为不可逆操作，**执行前必须与用户确认**是否保留数据。

### 9.0 清理前准备

- **决策点（必须先与用户确认）**：
  - 保留数据：只停服务与移除运行态资源，**不删**数据卷 / PVC / 数据库
  - 清除数据：追加执行删除数据卷 / PVC / 数据库的命令（不可逆）
- 建议先记录当前资源清单，便于核对清理结果：
  ```bash
  # Docker
  docker compose -f skeleton/docker/docker-compose.yml ps -a
  docker volume ls | grep -i mysql
  # 普通机器
  systemctl status skeleton --no-pager | head -20
  # K8s
  kubectl -n fh-skeleton get all,pvc
  ```

### 9.1 普通机器（JDK + MySQL + nginx + systemd）

```bash
# ① 停止并禁用后端服务
sudo systemctl disable --now skeleton
sudo systemctl daemon-reload

# ② 移除 nginx 站点配置并重载
sudo rm -f /etc/nginx/conf.d/skeleton-ui.conf && sudo nginx -t && sudo systemctl reload nginx
# 可选：移除前端静态产物
# sudo rm -rf /usr/share/nginx/html/skeleton-ui

# ③ 【可选】删除后端产物与 systemd unit
# 确认后执行：
# sudo rm -f /etc/systemd/system/multi-user.target.wants/skeleton
# sudo rm -f /etc/systemd/system/skeleton.service
# sudo rm -rf /opt/fh-skeleton
# sudo rm -f /etc/fh-skeleton.env
# 运行用户（如不再使用）：sudo userdel -r fhskeleton

# ④ 【可选】删除数据库与用户（保留则跳过）
# sudo mysql <<'SQL'
# DROP DATABASE IF EXISTS fh_skeleton;
# DROP USER IF EXISTS 'fh_skeleton'@'localhost';
# FLUSH PRIVILEGES;
# SQL

# ⑤ 验证：服务不存在/已停，8080 与 80 端口无进程监听
```

### 9.2 Docker Compose

> 注：`skeleton/docker/docker-compose.yml` 内置 `skeleton` + `fh-ui` 两服务；mysql 容器与 `mysql-data` 命名卷在 `skeleton/deploy-compose.yml`（deploy.sh 同步远端为 `docker-compose.yml`）。

```bash
# 保留数据：停止并移除容器（默认 compose 网络也会删除）
docker compose -f skeleton/docker/docker-compose.yml --env-file skeleton/deploy.env down

# 清除数据：追加删除命名数据卷（不可逆）
docker compose -f skeleton/docker/docker-compose.yml --env-file skeleton/deploy.env down -v

# 【可选】删除本地镜像（确认后执行）
docker rmi <REGISTRY>/paas-sdk-devkit/skeleton:<TAG>
docker rmi <REGISTRY>/paas-sdk-devkit/skeleton-ui:<TAG>
docker image prune -f

# 验证：无 pf-devkit 容器与 mysql-data 卷残留
docker ps -a | grep pf-devkit
docker volume ls | grep mysql-data
```

> `down` 只移除容器与默认网络，**不删除命名卷** `mysql-data`；`down -v` 才会删除卷与其中数据。

### 9.3 Kubernetes

```bash
# ① 保留数据：删除 namespace（含其下全部资源）
kubectl delete namespace fh-skeleton

# ②【可选】清除数据：删除 PVC 或确认存储类回收策略
kubectl -n fh-skeleton get pvc          # 先确认 PVC 名称
kubectl delete pvc -n fh-skeleton --all

# 或仅删负载保留 PVC（可视需要）
kubectl -n fh-skeleton delete deployment skeleton-backend skeleton-frontend
kubectl -n fh-skeleton delete sts mysql
kubectl -n fh-skeleton delete svc skeleton-backend skeleton-frontend mysql
kubectl -n fh-skeleton delete ingress skeleton-ingress

# ③ 验证：namespace 与 PVC 均已移除
kubectl get ns,all -A | grep fh-skeleton
```

> `kubectl delete namespace fh-skeleton` 会级联删除该命名空间下的 **全部** 资源（含 PVC、Secret、ConfigMap）。仅需"停止保留数据"时，systemd/Docker 形态可选择性保留数据卷；K8s 的持久数据在 PVC（按 storageClass 默认 ReclaimPolicy=Delete 可能一并回收，按集群配置确认）。
