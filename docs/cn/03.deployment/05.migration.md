# V1.0.0 迁移至 V1.1.0

本文档适用于已部署上云 API 2 V1.0.0、计划切换到 V1.1.0 的用户。

由于 V1.1.0 进行了国产化与集群化改造，V1.0.0 **无法直接升级**到 V1.1.0，需要按「备份数据 → 清理旧版本 → 全新安装 V1.1.0 → 导入数据」的流程迁移。

## 1. 为什么无法直接升级

V1.1.0 相对 V1.0.0 进行了两项底层改造：

- **国产化改造**：V1.1.0 新增国产化硬件与操作系统适配，底层组件和运行环境随之调整，与 V1.0.0 不兼容。
- **集群化改造**：V1.1.0 由 V1.0.0 的单机部署改为集群化部署，数据存储结构发生变化；同时许可证绑定方式也有调整——上云 API 2、Terra、4G 的许可证须绑定同一台授权服务器。

因此，V1.0.0 不支持通过可视化部署或命令行的方式原地升级到 V1.1.0。迁移时需要先卸载 V1.0.0，再全新安装 V1.1.0，并通过迁移脚本把 V1.0.0 运行期间产生的业务数据迁移过来。

迁移脚本用于**迁移业务数据**，不会自动卸载旧版本；旧版本的清理需要您按「3.2 清理旧版本 」小节单独执行。

## 2. 迁移流程总览

迁移流程分为以下六个阶段：

```
迁移前准备 → 备份数据 → 清理旧版本 → 全新安装 V1.1.0 → 导入数据 → 业务验证
```

| 阶段 | 执行位置 | 使用的脚本 |
|---|---|---|
| 备份数据 | V1.0.0 服务器 | `fh2-backup.sh` |
| 清理旧版本 | V1.0.0 服务器 | `environment-clean.sh` |
| 全新安装 V1.1.0 | 目标服务器 | 参考 [开始部署](./02.installation.md) |
| 导入数据 | V1.1.0 集群 | `fh2-restore.sh` |

> **说明：** 迁移脚本随 V1.1.0 安装包提供。脚本需以 **root** 身份，在脚本所在目录执行。

### 2.1 迁移前准备

- 确认目标服务器的硬件、操作系统满足 [部署前准备](./01.prerequisites.md) 的要求。
- 评估业务数据量，预估备份与迁移所需时间，**提前安排维护窗口**。备份期间相关业务服务会停止。
- 提前完成 [申请许可证](../02.apply-license.md)，准备好 V1.1.0 的许可证和安装包。
- 建议先在测试环境完整演练一遍迁移流程，确认业务可用后再对生产环境操作。
- 迁移前请务必**妥善保管备份数据**，以便在必要时重装 V1.0.0 并恢复数据。

---

## 3. 迁移步骤

### 3.1 备份数据

在 **V1.0.0 服务器**上以 root 身份执行：

```bash
./fh2-backup.sh -f <备份目录>
```

| 参数 | 说明 |
|---|---|
| `-f`（`--force`） | 备份前先清空已存在的备份目录再写入，请确认目录内没有需要保留的内容 |
| `--skip-data-path` | 跳过 data 目录的整体归档，适用于 data 目录数据量很大、需要自行迁移的场景 |

**需要迁移的数据：** 服务运行过程中产生的业务数据，包括配置、数据库、对象存储和静态文件，具体涉及组织、项目、设备、媒体（图片、视频等媒体文件）、航线和地图等。日志数据重要性较低。

> **注意：**
> - 备份期间会**停止相关业务服务**，备份脚本结束后会自动恢复旧服务。
> - 备份完成后，请**暂停业务使用和数据写入**，直到迁移完成，避免新产生的数据丢失。
> - 请将备份目录复制到安全的位置保存。

---

### 3.2 清理旧版本

确认备份已妥善保存后，在 **V1.0.0 服务器**上执行：

```bash
./environment-clean.sh
```

该脚本默认无交互执行，会按固定顺序卸载 V1.0.0 的相关服务。

> **注意：** 此操作不可逆，执行前请再次确认备份完整。

---

### 3.3 全新安装 V1.1.0

清理完成后，按照 [开始部署](./02.installation.md) 在原服务器上完成 V1.1.0 的全新安装。

- 原来是单机部署的，可先以单节点形态安装，数据迁移验证完成后再按需参考 [1.8 添加集群节点](./02.installation.md#_1-8-添加集群节点（可选）) 扩容为多节点集群。
- 安装完成并能正常访问 AIO 管理后台（端口 `30888`）后，再进行下一步。

---

### 3.4 导入数据

在 **V1.1.0 集群**上，以 root 身份执行：

```bash
./fh2-restore.sh -f <备份目录>
```

`<备份目录>` 为「3.1 备份数据」中保存备份数据的位置。脚本会处理单机版与集群版的数据结构差异，例如合并同名数据库、导入地图瓦片并重建索引。

---

## 4. 业务验证

导入完成后请逐项核对：

| 验证项 | 预期结果 |
|---|---|
| 组织、项目 | 数据完整 |
| 设备 | 数据完整，机场、飞行器等设备可重新连接并上线 |
| 媒体库 | 图片、视频等媒体文件数据完整 |
| 航线 | 数据完整 |
| 地图 | 数据完整，地图显示与切换正常 |
| AIO 管理后台 | 可正常访问 |

确认业务稳定后，再恢复正式业务使用。

## 5. 常见问题（FAQ）

**Q1：迁移后原来的设备还需要重新配置吗？**

- 迁移的是业务数据，设备需要重新连接到 V1.1.0 平台并确认上线状态。
- 如果对外访问 IP 与原来不一致，设备需要重新上云。

**Q2：数据导入失败怎么办？**

- 请保留备份目录和脚本输出日志。
- 需要回退时，可重新安装 V1.0.0 并使用备份数据恢复，之后联系技术支持协助排查。
