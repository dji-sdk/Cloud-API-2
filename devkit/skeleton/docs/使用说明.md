# FH Skeleton 使用说明

## 1. 项目简介

FH Skeleton 是基于 DJI Cloud API 2 SDK 的集成商快速接入骨架项目。它提供了一个开箱即用的全栈应用模板，集成商开发者只需关注业务逻辑，即可快速完成无人机管理平台的搭建。

### 核心特性

- **Mock/SDK 双模式**：本地开发使用 Mock 模式（无需真实硬件），生产使用 SDK 模式对接 DJI Cloud API 2
- **模块化架构**：按功能领域拆分为独立 Feature 模块，按需组合
- **前后端分离**：Spring Boot 后端 + Vue 3 前端，独立开发部署
- **AI 助手集成**：内置 ChatBot 功能，支持 MCP Tool 调用 + RAG 知识增强
- **完整鉴权体系**：JWT + RBAC 用户认证，开箱即用
- **一键部署**：提供 Docker Compose + SSH 远端部署脚本

### 技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| 后端框架 | Spring Boot | 3.2.5 |
| AI 集成 | Spring AI | 1.1.8 |
| 数据库 | MySQL 8.0 + Spring Data JPA | — |
| 前端框架 | Vue 3 + TypeScript + Vite 6 | — |
| 前端组件 | FH2 PaaS 前端 SDK（驾驶舱/航线/设备） | — |
| 地图引擎 | CesiumJS | 1.117.0 |
| Java 版本 | JDK 17+ | — |
| 构建工具 | Maven 多模块 / npm | — |

## 4. 快速启动

### 4.1 Docker Compose 一键启动（推荐新手）

`skeleton/docker/docker-compose.yml` 只包含后端和前端两个服务，**没有 MySQL 服务**；`skeleton/docker/.env.example` 也不含任何数据库 / JWT 变量。因此必须叠加 `skeleton/docker/deploy-local-mock.override.yml`，由它额外启动 `mysql:8.0` 并注入 `FH_DB_URL`、`FH_JWT_SECRET`、`FH_SDK_MODE=mock`。

首次使用先编辑 `skeleton/deploy.env.local-mock`，填写 `MYSQL_ROOT_PASSWORD` / `FH_DB_PASSWORD`（两者保持一致）和 `FH_JWT_SECRET`（可用 `openssl rand -hex 32` 生成；模板里的 `CHANGE_ME_*` 占位值必须替换，否则服务端拒绝启动）：

```bash
docker compose -f skeleton/docker/docker-compose.yml \
               -f skeleton/docker/deploy-local-mock.override.yml \
               --env-file skeleton/deploy.env.local-mock up --build
```

启动完成后：
- 后端服务：`http://localhost:8081`
- 前端页面：`http://localhost:8082`

### 4.2 本地开发启动（前后端分离）

适合日常开发调试，支持热重载。

#### 步骤 1：启动后端（Mock 模式）

```bash
cd skeleton

# 编译整个项目（宿主机构建需先安装私有 SDK JAR，见 README 前置条件）
mvn clean package -DskipTests

# 启动前需准备：
# 1. 本机可连的 MySQL 8.0（mock profile 同样使用 MySQL，不内置 H2；空库会由 JPA 自动建表）
# 2. FH_JWT_SECRET 必填，至少 32 字节
# 3. FH_DB_URL / FH_DB_USERNAME / FH_DB_PASSWORD 指向上述 MySQL
# 4. FH_SDK_MODE=mock —— 可选：application-mock.yml 已将 fh.skeleton.sdk.mode 设为 mock，
#    仅激活 mock profile 即可；显式设置便于阅读并防止 profile 与 mode 错配
export FH_SKELETON_PROFILE=mock
export FH_SDK_MODE=mock
export FH_JWT_SECRET=$(openssl rand -hex 32)
export FH_DB_URL='jdbc:mysql://localhost:3306/fh_skeleton?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
export FH_DB_USERNAME=root
export FH_DB_PASSWORD=your-mysql-password
java -jar app/fh-skeleton-app/target/fh-skeleton-app-0.1.0.jar
```

> 上述变量在 4.1 的 Docker Compose 方式中已由覆盖文件自动配置，无需手动导出。

后端默认在 `http://localhost:8080` 运行，API 基础路径为 `/pf-devkit/ai-plugin/skeleton`。

#### 步骤 2：启动前端

```bash
cd skeleton/web

# 安装依赖
npm install

# 配置环境变量
cp .env.example .env
# 编辑 .env 填写 FH2 服务器地址等
# 注意：.env.example 默认 VITE_MOCK_ENABLED=false，即使用真实后端数据，不会产生假 token

# 启动开发服务器
npm run dev
```

前端开发服务器运行在 `http://localhost:5173`，API 请求自动代理到后端 8080 端口。

### 4.3 验证启动成功

1. 访问前端 `http://localhost:5173`，应显示登录页面
2. **创建首个账号**：开放注册默认关闭（`FH_USER_REGISTRATION_ENABLED` 缺省为 `false`），直接点"注册"会返回
   `注册功能未开放，请联系管理员创建账号`。首次引导需临时开启注册：
   ```bash
   export FH_USER_REGISTRATION_ENABLED=true   # 重启后端生效
   ```
   注册完成后**立即关闭**该开关并重启（`FH_USER_REGISTRATION_ENABLED=false` 或删掉该变量）。
   注意首个注册用户会自动成为 `admin`，因此开启窗口期只能在可信网络内进行，切勿在公网暴露时开启。
3. 登录后进入仪表盘首页

Mock 模式下，系统会自动生成模拟设备数据，可在设备管理页面查看。

## 5. 配置说明

### 5.1 后端配置

所有配置通过环境变量注入，支持 `application.yml` 中的 `${VAR:default}` 语法。

#### 核心变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `FH_SKELETON_PORT` | `8080` | 后端服务端口 |
| `FH_SKELETON_PROFILE` | `sdk` | Spring profile：`mock` 为本地开发的可选项，生产固定 `sdk` |
| `FH_SDK_MODE` | `sdk` | SDK 子系统模式：`mock`（本地，配合 mock profile）/ `sdk`（生产） |
| `FH_JWT_SECRET` | **无默认，必填** | JWT 签名密钥，至少 32 字节；缺失时 compose 直接失败，占位值（`<...>` / `CHANGE_ME...`）会被服务端拒绝启动 |
| `FH_DB_URL` | `jdbc:mysql://localhost:3306/fh_skeleton...` | 数据库 JDBC URL |
| `FH_DB_USERNAME` | `root` | 数据库用户名 |
| `FH_DB_PASSWORD` | 空 | 数据库密码 |
| `FH_DDL_AUTO` | `update` | JPA DDL 策略，生产建议 `validate` |

#### SDK 模式变量（生产必填）

| 变量 | 说明 |
|------|------|
| `FH_SKELETON_SDK_ADDRESS` | DJI Cloud API 2 服务器地址 |
| `FH_SKELETON_SDK_TOKEN` | SDK 访问令牌 |
| `FH_SKELETON_SDK_PORT` | SDK 端口（默认 443） |
| `FH_SKELETON_SDK_NOTIFICATION_SERVER` | 事件通知服务器地址 |

#### Chat Bot 变量（可选）

| 变量 | 说明 |
|------|------|
| `fh.chat.enabled` | 是否启用 ChatBot（默认 `false`） |
| `FH_CHAT_MODEL` | AI 模型名称 |
| `SPRING_AI_OPENAI_API_KEY` | OpenAI 兼容 API Key |
| `SPRING_AI_ANTHROPIC_API_KEY` | Anthropic API Key |
| `FH_CHAT_MCP_URL` | MCP Server 连接地址 |
| `FH_CHAT_MCP_AUTH_TOKEN` | MCP Server 鉴权 Token |

### 5.2 前端配置

前端配置位于 `web/.env`，构建时注入。部署后通过 `docker-entrypoint.sh` 支持运行时覆盖。

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VITE_FH2_ADDRESS` | — | FH2 PaaS 前端服务器地址（含协议，不含端口） |
| `VITE_FH2_PORT` | `30812` | FH2 后端端口 |
| `VITE_FH2_WSS_URL` | — | WebSocket 通知推送地址 |
| `VITE_FH2_PRJ_ID` | — | FH2 项目 ID |
| `VITE_DEFAULT_THEME` | `dark` | 默认主题：`dark` / `light` |
| `VITE_PRIMARY_COLOR` | `#1a73e8` | 品牌主色 |
| `VITE_MOCK_ENABLED` | `false` | 前端假数据总开关。为 `true` 时 auth / wayline / flightTask / liveStream / dashboard 返回本地假数据，登录会拿到假 token；devices / media 等模块仍走真实后端，假 token 会 401。仅前端完全离线演示时开启 |
| `VITE_MOCK_DEBUG_PANEL` | `false` | 是否显示 `/mock-debug` 调试面板入口与路由。面板调用后端 mock 接口，与前端假数据开关无关 |
| `VITE_MAP_PROVIDER` | `esri` | 地图底图提供商 |

#### 地图底图选项

| 值 | 说明 | 是否需要 Key |
|----|------|-------------|
| `esri` | ESRI 卫星影像（默认） | 否 |
| `osm` | OpenStreetMap 矢量地图 | 否 |
| `bing` | Bing 卫星+标注 | 是（`VITE_BING_KEY`） |
| `tianditu` | 天地图卫星+中文标注（国内推荐） | 是（`VITE_TIANDITU_KEY`） |
| `natural-earth` | Cesium 内置低分辨率底图 | 否 |

## 6. 功能模块使用

### 6.1 用户认证（feature-user）

提供完整的注册/登录/JWT 鉴权体系。

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/users/register` | POST | 注册新用户（首个用户自动为 admin）。默认关闭，需 `FH_USER_REGISTRATION_ENABLED=true` |
| `/api/v1/users/login` | POST | 登录获取 JWT Token |
| `/api/v1/users/me` | GET | 获取当前用户信息 |

**前端使用**：登录成功后 Token 存储在 localStorage，所有 API 请求通过 `authFetch()` 自动附加 `Authorization: Bearer <token>` 请求头。401 响应自动跳转登录页。

**角色说明**：
- `admin`：管理员，可访问用户管理页面
- `user`：普通用户

### 6.2 设备管理（feature-device）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/devices` | GET | 设备列表 |
| `/api/v1/devices/{sn}` | GET | 设备详情 |

**Mock 模式**：启动后约 3 秒自动触发设备上线事件，可在前端设备管理页面看到模拟设备。

**前端页面**：`/devices` — 展示设备列表，实时状态更新。

### 6.3 驾驶舱（CockpitView）

**前端页面**：`/cockpit`

嵌入 FH2 PaaS 驾驶舱组件，提供：
- 实时飞行监控
- 无人机视角地图
- 设备遥测数据展示

> 依赖 FH2 服务器正确配置（`VITE_FH2_ADDRESS`）。

### 6.4 航线管理（feature-wayline）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/waylines` | GET | 航线列表 |
| `/api/v1/waylines/import` | POST | 导入航线（KMZ 文件） |
| `/api/v1/waylines/batch-delete` | POST | 批量删除航线 |
| `/api/v1/waylines/batch-download` | POST | 批量下载航线 |
| `/api/v1/waylines/executions` | GET | 航线执行记录 |

**前端页面**：`/wayline` — 嵌入 FH2 航线编辑器组件，支持航线的可视化创建、编辑和预览。

### 6.5 飞行任务（feature-flight-area 相关）

| 前端页面 | 路由 | 说明 |
|----------|------|------|
| 飞行任务列表 | `/flight-tasks` | 查看和管理飞行任务 |
| 创建飞行任务 | `/flight-tasks/create` | 配置并创建新任务 |

### 6.6 飞行区域（feature-flight-area）

**前端页面**：`/flight-areas`

提供电子围栏和禁飞区的地图可视化管理：
- 在 Cesium 地图上绘制区域（多边形/圆形）
- 设置区域类型（禁飞区 / 限高区 / 工作区）
- 同步到设备端生效

### 6.7 媒体管理（feature-media）

**前端页面**：`/media`

浏览和下载无人机拍摄的照片与视频：
- 按设备、时间筛选
- 缩略图预览
- 文件下载

### 6.8 三维重建（feature-terra）

**前端页面**：`/models`

管理三维重建任务和成果：
- 创建正射影像 / 3D Mesh / 点云重建任务
- 查看重建进度
- 在线预览三维模型

### 6.9 实时视频（LiveStream）

**前端页面**：`/live-stream`

实时查看无人机视频流，支持多路画面显示。

### 6.10 飞行回放

**前端页面**：`/flight-replay`

嵌入 FH2 飞行记录回放组件，查看历史飞行轨迹和遥测数据。

### 6.11 AI ChatBot（feature-chat）

**前端入口**：页面右侧抽屉面板

ChatBot 提供自然语言交互能力：
- 流式对话（SSE）
- MCP Tool 调用（通过 MCP Server 操作 DJI Cloud API 2）
- Tool 执行确认（危险操作需用户确认后执行）
- RAG 知识库增强（自动检索相关文档作为上下文）
- 语音输入（需 HTTPS 环境）

**启用方式**：设置环境变量 `fh.chat.enabled=true` 并配置 AI Provider API Key。

详细配置参见 [RAG 使用指南](rag-usage-guide.md)。

### 6.12 仪表盘（feature-dashboard）

**前端页面**：`/`（首页）

展示运营数据概览：设备在线统计、飞行任务统计、告警概况等。

### 6.13 Mock 调试面板

**前端页面**：`/mock-debug`（仅 `VITE_MOCK_DEBUG_PANEL=true` 时可见）

Mock 模式专属调试工具，可手动触发模拟事件（设备上线、OSD 更新、任务进度等），方便前端开发调试。

## 7. 运行模式说明

### Mock 模式（本地开发）

```bash
FH_SKELETON_PROFILE=mock
FH_SDK_MODE=mock
```

- 无需 DJI Cloud API 2 SDK 原生库，macOS/Windows/Linux 均可运行
- 仍使用 MySQL 持久化（未内置 H2），需先准备好数据库连接
- 自动生成模拟设备和遥测数据
- MockRestController 提供事件触发接口（`/mock/devices/{sn}/*`）

**适用场景**：前端开发、UI 调试、功能演示、集成测试。

### SDK 模式（生产部署）

```bash
FH_SKELETON_PROFILE=sdk
```

- 接入真实 DJI Cloud API 2 SDK（JNI 原生库，**仅 Linux x86_64 与 Linux aarch64**；SDK 按架构分两个包，构建时须选与目标架构匹配的那一份）
- 需配置 SDK 连接参数（地址、Token）
- 使用 MySQL 持久化数据
- 对接真实无人机设备

**适用场景**：正式运营环境、与真实设备对接。

**编译方式**（需包含 real-sdk 模块）：

```bash
mvn clean package -Psdk-real -DskipTests
```

## 8. 部署

### 8.1 远端一键部署

项目提供开箱即用的远端部署方案：

```bash
# 1. 准备部署配置
cp skeleton/deploy.env.example skeleton/deploy.env
# 编辑 deploy.env 填写：
#   - 远端服务器 SSH 信息
#   - 镜像仓库地址
#   - 数据库密码
#   - JWT 密钥
#   - FH2 服务器地址

# 2. 记录远端主机指纹（首次）
ssh-keyscan -p 22 <your-server-ip> > skeleton/deploy_known_hosts

# 3. 执行部署
./skeleton/deploy.sh
```

部署脚本支持以下选项：

```bash
./skeleton/deploy.sh                 # 完整部署（后端 + 前端）
./skeleton/deploy.sh --backend-only  # 只部署后端
./skeleton/deploy.sh --tag=v1.2.3    # 指定镜像版本
```

### 8.2 HTTPS 配置（可选）

Web Speech API（语音输入）在 Chrome 非 localhost 环境要求 HTTPS。配置方式：

```bash
# 在 deploy.env 中配置
SSL_CERT_PATH=/opt/ssl/cert.pem
SSL_KEY_PATH=/opt/ssl/key.pem
HTTPS_PORT=8083
```

无证书时可生成自签名证书：

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /opt/ssl/key.pem -out /opt/ssl/cert.pem \
  -subj "/CN=<your-server-ip>"
```

### 8.3 数据库初始化

首次部署时，MySQL 容器自动执行 `deploy-init-sql/01-init.sql` 创建数据库和基础表结构。后续重启不会重复执行。

JPA 的 `ddl-auto=update` 策略会自动同步新增字段。生产环境建议改为 `validate` 并使用 Flyway/Liquibase 管理 schema 变更。

## 10. 后端开发指南

### 常用命令

```bash
cd skeleton

mvn clean package -DskipTests     # 快速编译
mvn test                          # 运行全部测试
mvn test -pl feature/feature-user # 单模块测试
mvn verify -Pci                   # 带覆盖率的完整验证
```

### 新增 Feature 模块

1. 在 `feature/` 下创建新 Maven 模块：

```bash
mkdir -p feature/feature-xxx/src/main/java/com/dji/fh/feature/xxx
mkdir -p feature/feature-xxx/src/main/resources/META-INF/spring
```

2. 编写 `pom.xml`（参考 `feature-device`）

3. 创建 AutoConfiguration：

```java
@AutoConfiguration
@ConditionalOnProperty(prefix = "fh.xxx", name = "enabled", havingValue = "true", matchIfMissing = true)
public class XxxAutoConfiguration {
    // Bean 定义
}
```

4. 注册自动配置：在 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 中添加全限定类名

5. 在 `app/fh-skeleton-app/pom.xml` 和根 `pom.xml` 的 `<modules>` 中添加依赖

### 消费 SDK 事件

```java
@Component
public class MyEventListener {

    @EventListener
    public void onDeviceOnline(DeviceOnlineEvent event) {
        String sn = event.getDeviceSn();
        // 处理设备上线
    }

    @EventListener
    public void onOsdUpdate(OsdUpdateEvent event) {
        // 处理遥测数据更新
    }
}
```

## 12. CI/CD

内部仓库使用 CI 完成测试、构建与部署（具体流水线配置属于内部运维范畴，未随本仓库对外分发）。

和 `skeleton/docs/部署指南.md` 自行搭建对应的构建/部署流程。

## 13. 常见问题

### Q: Mock 模式启动报 JWT 相关错误？

A: `FH_JWT_SECRET` 是必填项，即使 Mock 模式也需要设置。可用以下命令生成：

```bash
export FH_JWT_SECRET=$(openssl rand -hex 32)
```

如果错误是 `fh.user.jwt.secret 长度不足（当前 16 字节，最少 32 字节）`，说明**环境变量没进容器**而非密钥本身有问题：
16 正好是 `application.yml` 里 `${FH_JWT_SECRET}` 这段字面量的长度。`--env-file` 只影响 compose 插值，
变量还必须写在服务的 `environment:` 段才会注入容器。基线 `skeleton/docker/docker-compose.yml` 已改为缺失时 compose
直接报错退出，并透传 `FH_JWT_SECRET` / `FH_DB_*`；若仍看到该错误，请确认用的是最新 compose 文件。

### Q: 前端页面白屏，浏览器控制台报 Mixed Content？

A: FH2 PaaS 组件的脚本加载需要协议一致。如果前端通过 HTTPS 访问但 `VITE_FH2_ADDRESS` 配置为 HTTP，浏览器会拦截。确保协议一致或配置 HTTPS。

### Q: 设备管理页面看不到设备？

A: Mock 模式下，设备需等待 3-4 秒自动上线（由 MockEventScripter 定时触发）。也可通过 Mock 调试面板手动触发上线事件。

### Q: 如何切换到真实 SDK 模式？

A: 三步：
1. 使用 `-Psdk-real` profile 重新打包：`mvn clean package -Psdk-real -DskipTests`
2. 设置环境变量：`FH_SKELETON_PROFILE=sdk`
3. 配置 SDK 连接参数（地址、Token）

注意：真实 SDK 的 JNI 原生库仅支持 Linux x86_64 与 Linux aarch64；SDK 按架构分两个包（`libs/amd64`、`libs/arm64`），本地 Maven 构建前必须安装与本机架构匹配的那一份。

### Q: ChatBot 功能如何启用？

A: 设置以下环境变量后重启后端：

```bash
fh.chat.enabled=true
SPRING_AI_OPENAI_API_KEY=your-api-key   # 或 Anthropic
FH_CHAT_MCP_URL=http://your-mcp-server:8080
```

### Q: 部署脚本报 sshpass not found？

A: 安装 sshpass：
- macOS: `brew install hudochenkov/sshpass/sshpass`
- Ubuntu: `apt install sshpass`
