## 详细排障

### 1. StartupAuthValidator 拒绝启动

**现象**：容器立即退出，日志含 `Auth token is blank or uses a well-known placeholder`。

**原因**：`FH_SSE_AUTH_TOKEN` 留空或使用了公知占位值（如 `.env.example` 中的模板值）。

**修复**：
```bash
# 生成强随机 token
openssl rand -hex 32
# 将结果填入 .env 的 FH_SSE_AUTH_TOKEN 字段
# 重启容器
docker compose up -d --force-recreate
```

---

### 2. exec format error

**现象**：容器启动失败，`docker logs` 显示 `exec format error`。

**原因**：在 Apple Silicon（ARM64）上构建镜像时未指定 `--platform linux/amd64`，生成了 ARM 镜像，在 x86_64 服务器无法执行。

**修复**：
```bash
# 重新构建，强制指定平台
docker build --platform linux/amd64 -t dji/flighthub-mcp:latest .
# 重新传输和部署
```

---

### 3. 原生库 .so 加载失败

**现象**：`UnsatisfiedLinkError: libVolcEngineRTC.so: libXxx.so: cannot open shared object file`

**原因**：运行时镜像缺少 SDK 原生库的系统依赖（OpenGL/X11/音频库）。

**排查**：
```bash
# 进入容器检查缺失的库
docker exec -it pf-devkit-mcp bash
ldd /app/lib/*.so 2>&1 | grep "not found"
```

**修复**：使用项目提供的 `mcp/Dockerfile`（已包含完整依赖列表），勿自行精简。

---

### 4. GLIBC execstack 拒绝

**现象**：Ubuntu 26.04+ 环境，日志含 `execstack` 相关错误，SDK 加载失败。

**原因**：glibc 2.39+ 默认拒绝加载带 `execstack` 标记的 `.so`。

**修复**：在 docker-compose.yml 或 `docker run` 中设置环境变量：
```yaml
environment:
  GLIBC_TUNABLES: "glibc.rtld.execstack=2"
```

> `mcp/docker-compose.yml` 和 `Dockerfile` 已默认包含此配置。

---

### 5. Claude Code 看不到 MCP Server

**现象**：`/mcp` 面板完全不显示 FlightHub MCP，无警告。

**排查**：
1. 确认配置写在 `~/.claude.json`（非 `~/.claude/settings.json` 或 `~/.claude/.mcp.json`）
2. 确认 `mcpServers` 对象中包含配置项
3. 确认 JSON 格式无语法错误

**优先级规则**（高到低）：
- `~/.claude.json`（最高，GUI 操作写入此处）
- `~/.claude/settings.json`
- `~/.claude/.mcp.json`

**修复**：将配置移到 `~/.claude.json` 的 `mcpServers` 中，完全重启 Claude Code。

---

### 6. SSE 配置缺 type 字段

**现象**：`/mcp` 面板显示黄色 ⚠ 警告：`command: expected string, received undefined`

**原因**：SSE 配置缺少 `"type": "sse"` 字段，Claude Code 按 stdio 模式解析，找不到 `command` 字段。

**修复**：
```json
{
  "dji-cloud-api2": {
    "type": "sse",
    "url": "http://<server>:8080/pf-devkit/ai-plugin/mcp/sse"
  }
}
```

### 7. ready 返回 503

**现象**：`/pf-devkit/ai-plugin/mcp/ready` 返回 503。

**排查**：
```bash
# 检查 /status 端点获取详细状态
curl http://<server>:8080/pf-devkit/ai-plugin/mcp/status | python3 -m json.tool
# 查看启动日志
docker logs pf-devkit-mcp --tail 50
```

**常见原因**：
- 工具注册未完成（启动后 5-10 秒内正常）
- SDK 初始化失败（凭证错误）
- Session 管理器未就绪

**修复**：等待 15 秒再检查；如仍 503，查日志定位具体错误。

---

### 8. SSE 流被 Nginx 截断

**现象**：客户端连接 SSE 后短暂收到 `event:endpoint`，随后连接中断或无后续事件。

**原因**：Nginx 默认启用 `proxy_buffering`，SSE 长连接被缓冲。

**修复**（Nginx 配置）：
```nginx
location /pf-devkit/ai-plugin/mcp/sse {
    proxy_pass http://127.0.0.1:8080/pf-devkit/ai-plugin/mcp/sse;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 3600s;
    proxy_set_header Connection '';
}
```

---

### 9. 重连失败

**现象**：客户端断线后 `reconnect` 失败。

**排查**：
- 断线是否超过 grace period（默认 60 秒）？超时需重新 `fh_connect`
- token hash 是否与断连前一致？不一致被视为劫持攻击

**修复**：超过 grace period 的断线无法恢复，客户端需重新建立完整连接。可通过 `FH_GRACE_PERIOD` 调大宽限期。

---

### 10. Workspace 注册失败

**现象**：`registerWorkspaceToken` 返回 `sessionId=-1`。

**排查**：检查 `FH_ACCESS_TOKEN` 和 `FH_WORKSPACE_UUID` 是否正确（从 FlightHub 控制台重新获取）。

**说明**：SDK 内部已做 fallback 处理（使用默认 workspace 实例），不影响基本功能。

---

### 11. WebSocket 通知连接失败

**现象**：日志持续报 `CppWebSocket: URL 解析失败`。

**原因**：未配置 `notificationServerAddress`。

**影响**：不影响 HTTP 设备查询等功能，仅实时推送不可用。

**修复**：如需实时推送，配置 WebSocket 地址（需 FlightHub 运维提供）；否则忽略此日志即可。

---

## 通用排障流程

```
1. docker logs pf-devkit-mcp --tail 100    # 查看最新日志
2. curl .../health                          # 健康检查
3. curl .../status                          # 运维状态
4. docker inspect pf-devkit-mcp             # 容器配置/环境变量
5. docker exec -it pf-devkit-mcp env        # 实际生效的环境变量
```
