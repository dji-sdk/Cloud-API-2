# 三形态对比与选型

> 来源：`skeleton/docs/部署指南.md` §1。本文件是 AI 选型的动作依据。

## 三形态对比

| 形态 | 适用场景 | 复杂度 | 前置依赖 |
|------|----------|--------|----------|
| 普通机器 | 单机/小规模，已有物理机或虚拟机 | 中 | JDK17、MySQL8、nginx、systemd |
| Docker Compose | 单机容器化，便于迁移与版本管理 | 低 | Docker 24+、Docker Compose v2 |
| Kubernetes | 生产级高可用、多副本、弹性伸缩 | 高 | K8s 集群、镜像仓库 |

## 选型逻辑（AI 决策依据）

1. **探测结果驱动**：先跑 `prompts/env-probe.sh`，看 OS/架构/工具是否齐备
2. **规模驱动**：
   - 生产级高可用/多副本 → K8s（需集群 + 镜像仓库）
   - 单机容器化 → Docker Compose（推荐多数 ISV 首选，复杂度最低）
   - 已有物理机/虚拟机、不想引入容器 → 普通机器
3. **架构红线**：sdk 模式必须 Linux amd64。非 amd64 → 提示只能 mock 演示或换机

## 平台限制（必须告知用户）

- SDK JNI 原生库仅支持 **Linux x86_64（amd64）**
- macOS/Windows 仅能运行 mock 模式（本地开发/演示）

## 架构图

```
用户 ──80/443──▶ fh-ui（Nginx + Vue3 dist，端口 80）
                 └── /pf-devkit/ai-plugin/skeleton/* → proxy
                     ▶ skeleton（Spring Boot，8080，context-path=/pf-devkit/ai-plugin/skeleton）
                         ├─▶ mysql（3306）
                         └─▶ MCP Server（独立部署，Chat 启用时需要）
```

## 外部依赖清单

| 依赖 | 必需 | 说明 |
|------|------|------|
| MySQL 8.0+ | 是 | 用户模块持久化（t_user 表） |
| DJI CloudAPI2（SDK） | sdk profile 必需 | FH_SKELETON_SDK_* 连接参数 |
| MCP Server | 否（Chat 启用时是） | FH_CHAT_MCP_URL 指向 |
| Spring AI Provider | 否 | Chat 功能用，不配则 Chat 不可用 |
