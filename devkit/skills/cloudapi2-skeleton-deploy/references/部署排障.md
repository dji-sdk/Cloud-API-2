# 部署排障

> 来源：`skeleton/docs/部署指南.md` §9-10。AI 在用户回报报错时按"现象→排查动作"定位。

## 日志查看命令（先定位日志）

| 形态 | 命令 |
|---|---|
| 普通机器 | `journalctl -u skeleton -f` |
| Docker | `docker logs pf-devkit-skeleton-server --tail 100` |
| K8s | `kubectl -n fh-skeleton logs deployment/skeleton-backend --tail 100` |

## 现象 → 排查动作

| 现象 | 排查动作 |
|---|---|
| 启动失败：JWT 未配置 | `FH_JWT_SECRET` 必填（≥32 字节）。`openssl rand -hex 32` |
| 启动失败：SDK initialize | sdk profile 下 `FH_SKELETON_SDK_TOKEN/ADDRESS/PORT/NOTIFICATION_SERVER` 4 项齐全？构建是否 `-Psdk-real`？ |
| SDK 返回 `ERROR_INVALID_PARAM` | 4 个 SDK 必填 env 是否全有值；`printenv | grep FH_SKELETON_SDK_` |
| SDK 返回 `ERROR_INIT_FAILED` | token 失效/endpoint 不可达/证书校验失败；`curl -v https://<address>:<port>` 测网络 |
| `.so` 加载失败 | native lib 系统依赖缺失（libssl1.1 等）；非 amd64 平台；普通机器是否跑过 native-lib-extract.sh |
| 设备不出现（mock 模式） | ① 确认 `FH_SDK_MODE=mock` 已设置（仅 `FH_PROFILE=mock` 不够——Spring profile 只激活 application-mock.yml 配置文件，SDK 子系统装配条件读 `fh.skeleton.sdk.mode` 属性，默认 `sdk`）；② mock 等 3-4s 自动上线；③ 日志应有 `MockSdkStarter: Mock SDK 正在初始化` 而非 `RealSdkStarter` |
| Chat 不可用 | `FH_CHAT_ENABLED=true`？`FH_CHAT_MCP_URL` 可达？`curl -v <mcp-url>/pf-devkit/ai-plugin/mcp/health`？API Key？ |
| Chat LLM 401 | `SPRING_AI_OPENAI_API_KEY` 和 `SPRING_AI_OPENAI_BASE_URL` 是否正确配置？使用企业内部 LLM 时 base URL 不是默认 OpenAI 地址 |
| Chat RAG embedding 401 导致启动崩溃 | `FH_CHAT_ENABLED=true` + RAG 启用时，启动阶段会调 Embedding API 加载文档向量。若 API key 无效/不可达，Spring Boot **启动失败**（不仅是 WARN）。**mock 模式建议 `FH_CHAT_ENABLED=false`**，除非确实有有效的 AI API key |
| Chat MCP 连接 401 | `FH_CHAT_MCP_AUTH_TOKEN` 必须和 MCP Server 的 `FH_SSE_AUTH_TOKEN` 保持一致 |
| Dashboard 数据全空 (SDK HTTP 401) | 平台网关开启了鉴权，SDK 请求返回 `missing auth_keys header`。需在 deploy.env 中配置 `FH_SKELETON_SDK_AUTH_HEADER_KEY=user_id` + `FH_SKELETON_SDK_AUTH_HEADER_VALUE=<your-auth-value>`（值视平台配置而定，示例值为占位）。验证：日志中搜索 `SDK HTTP 鉴权 header 已设置` 确认生效 |
| deploy.env 变量已配但容器内为空 | `deploy-compose.yml` 的 `environment:` 段必须显式声明每个传入容器的变量。新增 env 后需同步更新 compose 文件 |
| 镜像已拉取但代码未生效 | `docker pull` 返回 `Image is up to date` 不代表包含最新代码。验证方法：`docker logs` 搜索预期日志行；`docker inspect <image> --format='{{.Created}}'` 对比合并时间。如不一致需重新构建推送镜像 |
| Harbor 拉取 401 unauthorized | 远端未登录镜像仓库。执行 `docker login -u <user> -p <pass> <registry-host>` |
| 语音输入提示"请允许麦克风权限" | 即使 HTTPS + 用户已授权仍报错：检查响应头 `Permissions-Policy`。若含 `microphone=()`（禁用）需改为 `microphone=(self)`。修改 `skeleton/web/nginx.conf` 对应行后重建前端镜像或 `nginx -s reload` |
| 前端报"FH2_ADDRESS 未配置" | `VITE_FH2_ADDRESS` 为空。**mock 模式也必填**——前端 `useFH2Config` 启动时校验非空。无真实 FH2 时填 `http://localhost` 占位即可通过校验 |
| 前端设备管理"初始化失败" | 设备管理页使用 FH2 Device Manager SDK（直连 FH2 平台 API），mock 模式无有效 FH2 会话。**解法**：`VITE_FH2_DEVICE_SDK_ENABLED=false`，前端回退为后端 REST API 设备列表。SDK 模式（真实 FH2 连接）下保持 `true` 或不设。若 SDK 模式也报此错：检查浏览器能否访问 `${VITE_FH2_ADDRESS}/paasjs-demo/device-manager-sdk/index.js`、控制台 CORS/CSP 错误 |
| 驾驶舱点击后跳转回 welcome 页 | **根因**：`VITE_MOCK_ENABLED=true`（运行时）使前端 `login()` 返回硬编码假 token `mock-jwt-token-for-local-dev`，而 `fetchDevices()` 等 API 无 mock 分支，拿假 token 请求后端 → 401 → `authFetch` 全局拦截器清除 localStorage 并跳转 /welcome。**解法**：`VITE_MOCK_ENABLED=false`（本地部署应始终连接真实后端登录，不走前端 mock 登录流程）。附注：`VITE_FH2_SDK_AUTH_KEY/VALUE` 也应留空以避免 FH2 SDK CORS 问题 |
| 前端 404 | 静态产物未部署/SPA fallback 未生效 |
| 前端地图不显示 | `VITE_MAP_PROVIDER` 与 key 匹配（bing/tianditu 需 key） |
| SSE 被 nginx buffer | 反代 `/pf-devkit/ai-plugin/skeleton/` 需 `proxy_buffering off` + 300s 超时（skeleton-ui.conf 已含） |
| 健康检查超时 | SDK native lib 加载慢，放大 `initialDelaySeconds`/`start_period` |
| MySQL 初始化脚本没执行 | 数据卷已有数据时 `/docker-entrypoint-initdb.d/` 不执行；清空卷后重启 |
| 后端起不来 | 排查顺序：JWT → DB 连通 → SDK 凭据 |
