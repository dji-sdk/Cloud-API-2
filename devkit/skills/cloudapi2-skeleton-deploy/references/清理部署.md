# 清理部署（卸载）

> 来源：`skeleton/docs/部署指南.md` §9。AI 按此步骤清单推进，每步给命令等用户回报。
> 适用：对已部署的 FH Skeleton 做停止/移除/卸载。**清理属危险操作，必须先确认"保留数据 or 清除数据"。**

## 启动协议（硬规则）

1. **先问数据去向**：`保留数据（只停服务/移除运行态资源）` vs `清除数据（追加删除卷/PVC/库，不可逆）`。用户未明确前禁止执行任何删除命令
2. 每步只给一个命令（或一组强相关命令），等用户回报输出后再继续
3. 对 `rm -rf` / `DROP DATABASE` / `kubectl delete namespace` / `docker compose down -v` 等删数据命令，**必须逐条二次确认**
4. 清理结束后引导用户验证（无残留进程/容器/namespace 数据）

## 清理前资源清单

| 形态 | 查看命令 |
|---|---|
| 普通机器 | `systemctl status skeleton --no-pager \| head -20`、`ls /opt/fh-skeleton /etc/fh-skeleton.env` |
| Docker | `docker compose -f skeleton/docker/docker-compose.yml ps -a`、`docker volume ls \| grep mysql-data` |
| K8s | `kubectl -n fh-skeleton get all,pvc` |

## 普通机器（JDK + MySQL + nginx + systemd）

```bash
# ① 停止并禁用后端服务
sudo systemctl disable --now skeleton
sudo systemctl daemon-reload

# ② 移除 nginx 站点配置并重载
sudo rm -f /etc/nginx/conf.d/skeleton-ui.conf && sudo nginx -t && sudo systemctl reload nginx
# 可选：移除前端静态产物
# sudo rm -rf /usr/share/nginx/html/skeleton-ui

# ③ 【确认后】删除后端产物与 systemd unit
# sudo rm -f /etc/systemd/system/multi-user.target.wants/skeleton
# sudo rm -f /etc/systemd/system/skeleton.service
# sudo rm -rf /opt/fh-skeleton
# sudo rm -f /etc/fh-skeleton.env
# 运行用户（如不再使用）：sudo userdel -r fhskeleton

# ④ 【确认后】删除数据库与用户（保留则跳过）
# sudo mysql <<'SQL'
# DROP DATABASE IF EXISTS fh_skeleton;
# DROP USER IF EXISTS 'fh_skeleton'@'localhost';
# FLUSH PRIVILEGES;
# SQL

# ⑤ 验证
systemctl status skeleton --no-pager   # 应显示 inactive/dead 或不存在
ss -ltnp | grep -E ':8080|:80'
```

> 部署文档 §4.1 提到 `systemctl enable --now skeleton`；单位文件默认 enable 时生成 `multi-user.target.wants` 软链，清理需一并移除。

## Docker Compose

```bash
# 保留数据：停止并移除容器（默认 compose 网络一并删除）
# 注：docker/docker-compose.yml 内置 skeleton + fh-ui 两服务（无 mysql）；
#     部署形态 deploy-compose.yml 含 mysql，由 deploy.sh 同步为远端 docker-compose.yml
cd skeleton/docker && docker compose -f docker-compose.yml down
# 或远端部署形态（Harbor 拉取 + deploy.sh 拉起，执行位置在部署机 skeleton/）
docker compose -f skeleton/docker/docker-compose.yml --env-file skeleton/deploy.env down

# 【确认后】清除数据：追加删除命名数据卷（不可逆，mysql 数据在 mysql-data 卷）
docker compose -f skeleton/docker/docker-compose.yml --env-file skeleton/deploy.env down -v

# 【确认后，可选】删除本地镜像
docker rmi <REGISTRY>/paas-sdk-devkit/skeleton:<TAG>
docker rmi <REGISTRY>/paas-sdk-devkit/skeleton-ui:<TAG>
docker image prune -f

# 验证
docker ps -a | grep pf-devkit          # 无输出
docker volume ls | grep mysql-data     # 保留数据时有；清除数据后无
```

> docker-compose.yml 服务：`pf-devkit-skeleton-server`（skeleton）、`pf-devkit-skeleton-web`（fh-ui）；mysql 容器 `pf-devkit-mysql` 与数据卷 `mysql-data` 定义在 `deploy-compose.yml`。
> `deploy.sh` 仅自动拉起（pull + up），**不含 down/卸载**；清理时按上方 compose down 命令执行。

## Kubernetes

```bash
# ① 保留数据：删除 namespace（级联移除其下全部资源）
kubectl delete namespace fh-skeleton
#   - 此操作会删除该命名空间下 pods / svc / sts / deploy / configmap / secret / ingress / pvc（按 storageClass 默认 ReclaimPolicy 回收）

# 【确认后】清除数据：单独删除 PVC（若未随 namespace 删除）
kubectl -n fh-skeleton get pvc
kubectl delete pvc -n fh-skeleton --all

# 或仅删负载、保留 PVC（按需）
kubectl -n fh-skeleton delete deployment skeleton-backend skeleton-frontend
kubectl -n fh-skeleton delete sts mysql
kubectl -n fh-skeleton delete svc skeleton-backend skeleton-frontend mysql
kubectl -n fh-skeleton delete ingress skeleton-ingress

# 验证
kubectl get ns,all -A | grep fh-skeleton   # 无输出
```

> 资源名：namespace `fh-skeleton`、ingress `skeleton-ingress`、sts `mysql`、svc `skeleton-backend / skeleton-frontend / mysql`、PVC 由 `02-mysql-sts.yaml` 的 volumeClaimTemplates 生成（名称形如 `data-mysql-<index>-0`）。
> 删除 namespace 会级联删除全部资源（含 PVC）——**想保留数据时不要用 namespace 级联删除**，应改用"仅删负载"并保留 PVC（确认 storageClass 的 ReclaimPolicy 非 Delete，或后续主动回收）。

## AI 推进要点

- 每步命令执行后，让用户回报关键输出（如 `ss -ltnp`、`docker volume ls`、`kubectl get pvc`）
- 不确定数据是否仍需保留 → 一律按"保留数据"推进，删除命令全部列为【确认后】可选步骤
- 报错/残留 → 加载 references/部署排障.md（或按 §9 回查部署指南）
