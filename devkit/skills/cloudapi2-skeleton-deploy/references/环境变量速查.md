# 环境变量速查

> 来源：`skeleton/docs/部署指南.md` §7。AI 填配置时的唯一变量来源。

## 后端必填（缺失即停）

| 变量 | 默认 | 生成/获取 | 说明 |
|------|------|-----------|------|
| `FH_JWT_SECRET` | 无 | `openssl rand -hex 32` | JWT HS256 密钥，至少 32 字节 |
| `FH_DB_URL` | `jdbc:mysql://localhost:3306/fh_skeleton...` | 按形态填 | 数据库 JDBC URL |
| `FH_DB_USERNAME` | `fh_skeleton` | — | 数据库用户 |
| `FH_DB_PASSWORD` | 无 | `openssl rand -hex 24` | 数据库密码 |
| `FH_SKELETON_SDK_TOKEN` | — | DJI CloudAPI2 控制台 | SDK 身份令牌（sdk profile） |
| `FH_SKELETON_SDK_ADDRESS` | — | — | SDK 服务地址 |
| `FH_SKELETON_SDK_NOTIFICATION_SERVER` | — | — | SDK 通知服务地址 |

## 后端可选

| 变量 | 默认 | 说明 |
|------|------|------|
| `SPRING_PROFILES_ACTIVE` / `FH_SKELETON_PROFILE` | `sdk` | `sdk` / `mock` |
| `FH_SDK_MODE` | `sdk` | `mock` / `sdk`。**⚠️ mock 模式必填 `mock`**——仅设 `FH_PROFILE=mock` 不够，SDK 子系统按此属性决定装配 MockSDK 还是 RealSDK |
| `FH_SKELETON_PORT` | `8080` | 后端端口 |
| `FH_SKELETON_SDK_PORT` | `443` | SDK 端口 |
| `FH_DDL_AUTO` | `update` | JPA DDL 策略，生产建议 `validate` |
| `FH_CHAT_ENABLED` | `false` | 是否启用 Chat |
| `FH_CHAT_MCP_URL` | — | MCP Server 地址（Chat 启用时必填） |
| `FH_CHAT_MCP_AUTH_TOKEN` | — | MCP 鉴权 token |
| `FH_CHAT_PROVIDER` | `openai` | `openai` / `anthropic` |
| `FH_CHAT_MODEL` | `deepseek-v4-flash-private` | 主模型 |
| `SPRING_AI_OPENAI_API_KEY` | — | OpenAI 兼容 API Key |
| `SPRING_AI_ANTHROPIC_API_KEY` | — | Anthropic API Key |

## 前端

| 变量 | 默认 | 说明 |
|------|------|------|
| `VITE_FH2_ADDRESS` | — | FH2 服务器地址（含协议，不含端口）。**⚠️ mock 模式也必填**，前端 `useFH2Config` 启动时校验非空，为空则页面报错"FH2_ADDRESS 未配置"。无真实 FH2 时可填 `http://localhost` 占位 |
| `VITE_FH2_PORT` | `30812` | FH2 端口 |
| `VITE_FH2_WSS_URL` | — | FH2 WebSocket 通知地址 |
| `VITE_FH2_PRJ_ID` | — | FH2 项目 ID |
| `VITE_FH2_SDK_AUTH_KEY` | — | FH2 SDK 附加鉴权 header key。**⚠️ 应留空**——设置非空值（如 `user_id`）会导致 CORS 预检失败，驾驶舱页面闪退。FH2 网关鉴权由后端 `FH_SKELETON_SDK_AUTH_HEADER_KEY` 处理 |
| `VITE_FH2_SDK_AUTH_VALUE` | — | FH2 SDK 附加鉴权 header value。与 AUTH_KEY 配套，同样**应留空** |
| `VITE_FH2_DEVICE_SDK_ENABLED` | `true` | FH2 设备管理 SDK 开关。**mock 模式必须设 `false`**——该 SDK 直连 FH2 平台 API，mock 模式无有效 FH2 会话，SDK 初始化后内部 API 调用失败会渲染"初始化设备列表失败"。设 `false` 后前端回退为后端 REST API 设备列表 |
| `VITE_DEFAULT_THEME` | `light` | `light` / `dark` |
| `VITE_PRIMARY_COLOR` | `#1a73e8` | 品牌主色 |
| `VITE_MOCK_ENABLED` | `false` | **⚠️ 本地部署必须为 `false`**。设为 `true` 时前端 `login()` 跳过后端直接返回假 token，而设备/驾驶舱等 API 无 mock 分支，用假 token 请求后端 → 401 → 跳转 welcome 页。只有纯前端开发（无后端）时才设 `true` |
| `VITE_MAP_PROVIDER` | `esri` | `esri`/`osm`/`bing`/`tianditu` |
| `VITE_BING_KEY` | — | Bing 地图 key（运行时注入，勿 build-arg） |
| `VITE_TIANDITU_KEY` | — | 天地图 key（同上） |

## 常用生成命令

```bash
openssl rand -hex 32   # JWT / MCP auth token
openssl rand -hex 24   # DB / root 密码
```
