## 1. 部署架构与平台限制

### 1.1 平台支持矩阵

DJI Cloud API 2 SDK 为 **JNI 原生库，按 CPU 架构分成两个发布包**：`libs/amd64/flight-hub-sdk-3.3.7.jar` 内含 `lib/linux-x86_64/*.so`，`libs/arm64/flight-hub-sdk-3.3.7.jar` 内含 `lib/linux-aarch64/*.so`。镜像构建时通过 `--build-arg SDK_ARCH=amd64|arm64` 选包，**必须与目标运行架构一致**。

| 平台 | 真实 SDK | Mock 模式 | 说明 |
|------|----------|-----------|------|
| Linux x86_64 | ✅ 直接运行 JAR | ✅ | 生产部署目标（用 `SDK_ARCH=amd64` 构建镜像） |
| Linux aarch64 | ✅ 直接运行 JAR | ✅ | 生产部署目标（用 `SDK_ARCH=arm64` 构建镜像） |
| macOS（Intel/Apple Silicon） | ❌ | ✅ | 需 Docker 选对 `--platform` 并配对的 `SDK_ARCH` 跑真 SDK |
| Windows | ❌ | ✅ | 同上 |
| 任意平台 | — | ✅ `FH_MOCK=true` | 跳过 SDK 初始化，返回模拟数据 |

### 1.2 传输模式

| 模式 | 适用场景 | 鉴权 | 多用户 | 重连 |
|------|----------|------|--------|------|
| stdio | 本地 IDE（Claude Code/Cursor） | 环境变量 | 单 session | 不支持 |
| sse | Docker / 远程 Agent | Bearer Token 或 JWT | per-client | 支持（grace period 60s） |

生产部署默认用 **SSE 模式**。基础路径 `/pf-devkit/ai-plugin/mcp`（`spring.webflux.base-path`）。

## 2. 【推荐】AI 辅助部署

> **5 分钟完成部署**：安装部署 Skill 后，AI 会根据你的环境自动引导完成构建、配置、启动、验证全流程——无需逐节阅读本文档。

### 2.1 什么是部署 Skill

部署 Skill（`cloudapi2-mcp-deploy`）是一组 `.md` 规则文件，安装后 AI 就像一个熟悉 MCP Server 的运维工程师：

- **环境探测**：自动检测 OS、架构、Docker 版本、Java 版本、网络连通性、端口占用
- **配置生成**：强随机密钥（`FH_SSE_AUTH_TOKEN`、`FH_OPERATOR_TOKEN`）、完整 `.env` 文件
- **分步引导**：逐步给出精确命令，等你执行并回报结果后再进入下一步
- **即时排障**：遇到报错自动分析原因并给出修复命令（覆盖 11 种常见故障场景）

交互模式为**半自动**：AI 负责思考与生成，你负责执行系统级操作（`docker build`、`docker compose up` 等）并回报输出。

### 2.2 安装部署 Skill

#### 方式 A：Plugin 一键安装（推荐，需 Claude Code >= 1.0）

```bash
# 第 1 步：添加 Marketplace（仅首次）
claude plugin marketplace add https://github.com/dji-sdk/dji-cloudapi2-devkit.git

# 第 2 步：安装 plugin（含全部部署 Skill；marketplace 名 dji，plugin 名 cloudapi2）
claude plugin install cloudapi2@dji
```

> 私有部署环境把仓库地址换成内部 Git 仓库地址即可。

#### 方式 B：手动配置 settings.json

编辑 `~/.claude/settings.json`，添加：

```jsonc
{
  "enabledPlugins": {
    "cloudapi2@dji": true
  },
  "extraKnownMarketplaces": {
    "dji": {
      "source": {
        "source": "directory",
        "path": "/path/to/dji-flighthub-devkit"  // 替换为仓库绝对路径
      }
    }
  }
}
```

#### 方式 C：手动拷贝（仅部署 Skill）

```bash
cp -r skills/cloudapi2-mcp-deploy ~/.claude/skills/
```

### 2.3 启动 AI 引导部署

新开 Claude Code 会话，输入：

```
帮我把 MCP Server 部署到 Docker
```

或根据你的目标替换：

| 目标 | 对话示例 |
|------|---------|
| Docker 远程部署（生产） | "帮我把 MCP Server 部署到远程服务器" |
| 本地 Mock 开发 | "帮我本地 Mock 模式跑 MCP Server" |
| Docker stdio 代理 | "帮我用 Docker 跑 MCP Server 的 stdio 模式" |
| 部署排障 | "MCP Server 启动报 StartupAuthValidator 错误" |

AI 会自动：
1. 让你执行环境探测脚本，分析前置条件
2. 推荐部署形态（Docker SSE / 本地 stdio），与你确认
3. 生成强随机密钥，拼装完整配置文件
4. 逐步给出构建与启动命令
5. 验证健康检查端点
6. 遇到错误时自动路由到排障流程

### 2.4 验证 Skill 已生效

如果 AI 回复中提到以下内容，说明 `cloudapi2-mcp-deploy` Skill 已成功加载：

- "SSE 远程部署"或"stdio 本地开发"等部署形态
- "`FH_SSE_AUTH_TOKEN` 必填"或"StartupAuthValidator"
- "环境探测"或自动给出 `env-probe.sh` 脚本

### 2.5 与 skeleton 部署 Skill 的关系

如果你同时部署 skeleton 和 MCP Server（skeleton 的 Chat 功能依赖 MCP Server），两个 Skill 各自引导各自的部署流程：

| Skill | 部署目标 | 关键联调变量 |
|---|---|---|
| `cloudapi2-skeleton-deploy` | skeleton（后端 + 前端 + MySQL） | `FH_CHAT_MCP_URL`、`FH_CHAT_MCP_AUTH_TOKEN` |
| `cloudapi2-mcp-deploy` | MCP Server | `FH_SSE_AUTH_TOKEN` |

**跨 Skill token 一致性**：skeleton 的 `FH_CHAT_MCP_AUTH_TOKEN` 必须与 MCP Server 的 `FH_SSE_AUTH_TOKEN` 相同，否则 Chat 调用 MCP 会鉴权失败。两个 Skill 的密钥生成脚本会提示这一点。

> **不用 AI？** 继续阅读 §3 手动部署。

## 3. 手动部署

> 本章覆盖 MCP Server 手动部署全流程：构建 → 配置 → 运行 → 远端部署。按需阅读对应小节。

### 3.1 构建前置：私有 SDK JAR

SDK JAR 不在任何远端 Maven 仓库，必须随项目提交并本地安装。SDK 分 amd64 / arm64 两个包且 Maven 坐标相同，
按本机架构选一个安装。每台构建机第一次或 Docker 构建时执行：

```bash
mvn install:install-file \
  -Dfile=libs/amd64/flight-hub-sdk-3.3.7.jar \
  -DgroupId=com.dji.flighthubsdk \
  -DartifactId=flight-hub-sdk \
  -Dversion=3.3.7 \
  -Dpackaging=jar \
  --settings config/settings.xml
```

> arm64 构建机把 `-Dfile` 换成 `libs/arm64/flight-hub-sdk-3.3.7.jar`；两者坐标相同，`~/.m2` 中只能存在一份。

> Dockerfile 在构建阶段已内置此步骤；本地 `mvn package` 前需手动执行一次。

`config/settings.xml` 为集成商友好默认配置（仅用 Maven Central），可替换为内网 Nexus 镜像。

### 3.2 Maven 构建

| 命令 | 用途 | 产物 |
|------|------|------|
| `mvn clean package -DskipTests` | 快速构建 | `mcp/target/flighthub-mcp-server-1.0.0.jar` |
| `mvn clean package` | 含测试完整构建 | 同上 |
| `mvn verify -Pci` | CI 用，JaCoCo 覆盖率硬卡点（行覆盖 ≥ 60%） | 同上 + 覆盖率报告 |
| `mvn checkstyle:check` | 阿里巴巴规范检查 | — |

项目元数据：`groupId=com.dji.flighthub` / `artifactId=flighthub-mcp-server` / `version=1.0.0` / Java 17 / Spring Boot 3.4.1。

### 3.3 Docker 镜像构建

#### 多阶段 Dockerfile（`mcp/Dockerfile`）

**Stage 1 — 构建**（`eclipse-temurin:17-jdk` + Maven 3.9.9）：
1. 复制 `config/settings.xml` → `/root/.m2/`
2. 安装私有 SDK JAR（见 §3.1）
3. `mvn package -DskipTests`
4. 产物 `target/*.jar`

**Stage 2 — 运行**（`eclipse-temurin:17-jre`，Ubuntu 24.04 Noble）：
- 安装原生库系统依赖（图形/音频库，供 VolcEngine RTC / Agora 使用）：
  ```
  libatomic1 libgl1 libegl1 libgles2 libglib2.0-0 libx11-6 libxext6 libxrender1
  libxdamage1 libxfixes3 libxcomposite1 libxrandr2 libxi6 libxcursor1 libxinerama1
  libxtst6 libdrm2 libgbm1 libxshmfence1 libxxf86vm1 libpulse0 libasound2t64 curl
  ```
- 非 root 用户 `mcp:mcp`
- 暴露端口 `8080`
- 默认环境：`FH_TRANSPORT=sse`、`FH_SSE_PORT=8080`、`FH_MAX_SECURITY_LEVEL=2`、
  `JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0 -XX:+ExitOnOutOfMemoryError"`
- 启动：`java ${JAVA_OPTS} -jar /app/flighthub-mcp.jar --spring.profiles.active=sse`
- HEALTHCHECK：`curl -sf http://localhost:8080/pf-devkit/ai-plugin/mcp/health`，`--interval=30s --timeout=5s --start-period=15s --retries=3`

#### 本地构建镜像

```bash
cd mcp
mvn clean package -DskipTests
docker build --build-arg SDK_ARCH=amd64 -t dji/flighthub-mcp:latest .
```

> `SDK_ARCH` 必填，漏传直接构建失败。x86_64 服务器用 `amd64`，aarch64 服务器用 `arm64`；在 Apple Silicon 上跨架构构建 amd64 镜像时再加 `--platform linux/amd64`，`--platform` 与 `SDK_ARCH` 必须指向同一架构。

### 3.4 运行配置

#### 必填环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `FH_SERVER_ADDRESS` | — | DJI Cloud API 2 服务器地址（如 `https://your-server.com`） |
| `FH_ACCESS_TOKEN` | — | workspace-access-token 鉴权 |
| `FH_WORKSPACE_UUID` | — | workspace-binding-uuid |
| `FH_SSE_AUTH_TOKEN` | — | SSE 模式客户端鉴权 token，**留空或公知占位值会被 `StartupAuthValidator` 拒绝启动**。生成：`openssl rand -hex 32` |
| `FH_TRANSPORT` | stdio | `stdio` / `sse`（Docker 默认 sse） |
| `FH_SSE_PORT` | 8080 | SSE 监听端口 |
| `FH_MAX_SECURITY_LEVEL` | 2 | 最大安全等级 0-3，生产建议 2 |

#### 可选环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `FH_SERVER_PORT` | 443 | DJI Cloud API 2 服务器端口 |
| `FH_OPERATOR_TOKEN` | — | L3 操作员 token（紧急停机鉴权） |
| `FH_MOCK` | false | Mock 模式（跳过真实 SDK 初始化） |
| `FH_HEARTBEAT_INTERVAL` | 30000 | 心跳间隔（ms） |
| `FH_HEARTBEAT_TIMEOUT` | 300 | 连接空闲超时（s） |
| `FH_GRACE_PERIOD` | 60 | 重连宽限期（s） |
| `FH_SESSION_TIMEOUT` | 1800 | 会话超时（s） |
| `FH_COCKPIT_URL` | — | 驾驶舱前端地址，起飞成功后返回监看链接 |
| `FH_RATE_LIMIT_MAX` | 100 | 单 IP 每窗口最大请求数（SSE） |
| `FH_RATE_LIMIT_WINDOW_SECONDS` | 60 | 限流窗口（s） |
| `FH_RATE_LIMIT_TRUST_PROXY` | false | 是否信任 `X-Forwarded-For`（仅在受信反代后启用） |
| `FH_RATE_LIMIT_MAX_KEYS` | 10000 | 最大跟踪 IP 数（防 OOM） |
| `FH_CORS_ALLOWED_ORIGINS` | — | CORS 允许源（逗号分隔） |
| `FH_AUDIT_ENABLED` | true | 审计日志 |
| `FH_IDEMPOTENCY_ENABLED` | true | 幂等缓存（防重试重复飞行指令） |
| `FH_IDEMPOTENCY_TTL` | 300 | 幂等缓存 TTL（s） |
| `FH_FAILSAFE_ON_CRASH` | return_home | 无人机崩溃应对 |
| `FH_FAILSAFE_DISCONNECT_TIMEOUT` | 60 | 失联超时（s） |
| `GLIBC_TUNABLES` | — | `glibc.rtld.execstack=2`（Ubuntu 26.04+ 必设） |

完整模板见 `mcp/.env.example`。

#### Spring 配置

| 项 | 默认 | 说明 |
|----|------|------|
| `spring.webflux.base-path` | `/pf-devkit/ai-plugin/mcp` | 所有 HTTP 端点前缀 |
| `logging.level.com.dji.flighthub.mcp` | INFO | 业务日志 |
| `logging.level.io.modelcontextprotocol` | INFO | MCP 协议日志 |

### 3.5 本地运行

#### Mock 模式（任意平台，无需原生库）

```bash
cd mcp
FH_SERVER_ADDRESS=http://placeholder FH_MOCK=true \
  java -jar target/flighthub-mcp-server-1.0.0.jar \
  --spring.profiles.active=sse
# 访问 http://localhost:8080/pf-devkit/ai-plugin/mcp/sse
```

#### SSE 模式（`run-mcp-sse.sh`）

```bash
cd mcp
cp .env.example .env && vim .env   # 填写 FH_SERVER_ADDRESS / FH_SSE_AUTH_TOKEN 等
./run-mcp-sse.sh
```

JVM 默认 `-Xms64m -Xmx512m -XX:MaxMetaspaceSize=128m -XX:+UseG1GC`。

#### stdio 模式（`run-mcp-local.sh`）

供 Claude Code/Cursor 本地集成，自动过滤非 JSON 输出（仅 JSON-RPC 走 stdout）：

```bash
./run-mcp-local.sh
```

#### Docker stdio 代理（macOS/Windows 跑真 SDK）

```bash
docker run --rm -i --platform linux/amd64 \
  -e FH_TRANSPORT=stdio \
  -e FH_SERVER_ADDRESS="$FH_SERVER_ADDRESS" \
  -e FH_ACCESS_TOKEN="$FH_ACCESS_TOKEN" \
  -e FH_WORKSPACE_UUID="$FH_WORKSPACE_UUID" \
  dji/flighthub-mcp:latest \
  --spring.profiles.active=stdio \
  --spring.main.web-application-type=none
```

> `--platform` 必须与构建镜像时的 `SDK_ARCH` 一致：`SDK_ARCH=amd64` 配 `linux/amd64`，`SDK_ARCH=arm64` 配 `linux/arm64`。Apple Silicon 上构建 arm64 镜像后可直接省略 `--platform`。

> Claude Code MCP 配置示例见 [docker-deployment.md](./docker-deployment.md)。

### 3.6 远端部署（deploy.sh）

#### docker-compose.yml（`mcp/docker-compose.yml`）

```yaml
services:
  mcp:
    image: ${REGISTRY:-your-registry.example.com}/paas-sdk-devkit/mcp:${IMAGE_TAG:-latest}
    container_name: pf-devkit-mcp
    ports: ["8080:8080"]
    environment:
      FH_TRANSPORT: sse
      FH_SSE_PORT: "8080"
      FH_SSE_AUTH_TOKEN: ${FH_SSE_AUTH_TOKEN:?must set}
      FH_SERVER_ADDRESS: ${FH_SERVER_ADDRESS:-https://your-server.com}
      FH_SERVER_PORT: ${FH_SERVER_PORT:-443}
      FH_ACCESS_TOKEN: ${FH_ACCESS_TOKEN:-your-token}
      FH_WORKSPACE_UUID: ${FH_WORKSPACE_UUID:-your-uuid}
      FH_MAX_SECURITY_LEVEL: ${FH_MAX_SECURITY_LEVEL:-2}
      FH_OPERATOR_TOKEN: ${FH_OPERATOR_TOKEN:-}
      FH_SESSION_TIMEOUT: ${FH_SESSION_TIMEOUT:-1800}
      FH_WAYLINE_UPLOAD_DIR: /data/waylines   # KMZ 本地路径通道的允许目录
      JAVA_OPTS: "-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0"
      GLIBC_TUNABLES: "glibc.rtld.execstack=2"
    volumes:
      # 宿主机 KMZ 目录只读挂载；客户端放到 FH_WAYLINE_HOST_DIR 后，
      # 提交路径写容器内路径 /data/waylines/<file>.kmz
      - ${FH_WAYLINE_HOST_DIR:-./waylines}:/data/waylines:ro
    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8080/pf-devkit/ai-plugin/mcp/health"]
      interval: 30s
      timeout: 5s
      start_period: 15s
      retries: 3
    mem_limit: 1g
    memswap_limit: 1g
    restart: unless-stopped
```

#### deploy.sh 四阶段

```bash
./mcp/deploy.sh                  # 部署 latest
./mcp/deploy.sh --tag 20260801153045   # 指定版本
```

| 阶段 | 任务 |
|------|------|
| 1. 前置检查 | 校验 `sshpass`、`deploy.env`、SSH 密钥 |
| 2. 远端拉取 | `docker pull ${HARBOR_IMAGE}:${IMAGE_TAG}` |
| 3. 远端重启 | `cd ${REMOTE_DIR} && IMAGE_TAG=${TAG} docker compose up -d --force-recreate` |
| 4. 健康检查 | `curl http://${REMOTE_HOST}:8080/pf-devkit/ai-plugin/mcp/health`（最多 60s） |

#### deploy.env（从 `mcp/deploy.env.example` 复制）

```bash
REMOTE_HOST=<server-ip>
REMOTE_USER=<ssh-user>
REMOTE_PASS=<ssh-password>      # 通过 sshpass -e 环境变量传递，不落命令行
REMOTE_SSH_PORT=22
REMOTE_DIR=/opt/mcp             # 远端 docker-compose.yml 所在目录
REMOTE_PORT=8080                # 健康检查端口
```

#### SSH 安全

```bash
# 首次运行前生成主机指纹（文件含目标主机地址，按环境本地生成、不入库）
ssh-keyscan -p ${REMOTE_SSH_PORT:-22} "${REMOTE_HOST}" > mcp/deploy_known_hosts
```

> `deploy.sh` 检测到该文件缺失时会自动执行上面的 `ssh-keyscan`；扫描失败直接中止，
> 不会降级为 `StrictHostKeyChecking=no`。

#### KMZ 本地路径上传的挂载

`fh_workspace(action=submit)` 的本地路径通道要求 KMZ 文件对 MCP 进程可见：

| 运行方式 | 客户端生成位置 | 提交时的 `file_path` |
|---|---|---|
| 本机 stdio（`run-mcp-local.sh`） | `/tmp/wayline-xxxx.kmz` | 原样，同一文件系统 |
| Docker stdio（`run-mcp-docker.sh`） | 宿主机 `/tmp`（可用 `FH_WAYLINE_HOST_DIR` 覆盖） | `/data/waylines/wayline-xxxx.kmz` |
| 远端 SSE（docker-compose） | 远端 `FH_WAYLINE_HOST_DIR`（默认 `<compose 目录>/waylines`） | `/data/waylines/wayline-xxxx.kmz` |

> 远端 SSE 场景下，客户端与本服务不在同一台机器，本地路径通道**天然不可用**：
> 需先把 KMZ 放到远端挂载目录，或改用对象存储 key 形式提交。
> 挂载为只读（`:ro`），容器内 `mcp` 用户无需写权限。

## 4. 健康检查与监控

### 4.1 端点（认证豁免，K8s/负载均衡可直接访问）

| 端点 | 用途 | 响应 |
|------|------|------|
| `GET /pf-devkit/ai-plugin/mcp/health` | liveness | `{ "status":"UP", "timestamp":"..." }`，JVM 活着即 200 |
| `GET /pf-devkit/ai-plugin/mcp/ready` | readiness | 检查工具注册 + session 管理器，不就绪 503 |
| `GET /pf-devkit/ai-plugin/mcp/status` | 运维诊断 | 版本、uptime、工具数、活跃 session、JVM 内存 |

### 4.2 K8s Probe 建议

```yaml
livenessProbe:
  httpGet: { path: /pf-devkit/ai-plugin/mcp/health, port: 8080 }
  initialDelaySeconds: 10
  periodSeconds: 30
```

### 4.3 心跳与重连

- 客户端每 30s（`FH_HEARTBEAT_INTERVAL`）发 `ping`，服务端回 `{}`。
- 不活动超 300s（`FH_HEARTBEAT_TIMEOUT`）判死连接。
- 断线后 60s（`FH_GRACE_PERIOD`）内可 `reconnect` 恢复，控制权与 DRC 链路保留；超时需重新 `fh_connect`。

## 5. 生产环境建议

| 项 | 建议值 | 说明 |
|----|--------|------|
| `FH_MAX_SECURITY_LEVEL` | 2 | 仅允许飞行控制，禁用 L3 紧急停机（需远程停机才设 3 + `FH_OPERATOR_TOKEN`） |

| `FH_AUDIT_ENABLED` | true | 审计日志（Tool 执行、用户、成功/失败、错误） |
| `FH_IDEMPOTENCY_ENABLED` | true | 防重试重复飞行指令 |
| `FH_SSE_AUTH_TOKEN` | `openssl rand -hex 32` | 强随机，勿用占位值 |
| `FH_RATE_LIMIT_TRUST_PROXY` | false | 仅在受信反代后设 true |
| 内存限制 | 1g+ | docker-compose 默认 1g |
| 日志级别 | INFO | — |

## 6. 故障排查

| 现象 | 排查 |
|------|------|
| 启动失败：`StartupAuthValidator` 拒绝 | `FH_SSE_AUTH_TOKEN` 留空或用了公知占位值，生成 `openssl rand -hex 32` 后重填 |
| `.so` 加载失败 / `execstack` | 设 `GLIBC_TUNABLES=glibc.rtld.execstack=2`（Ubuntu 26.04+） |
| macOS/Windows 真 SDK 报错 | 必须用 Docker，且 `--platform` 与构建时的 `SDK_ARCH` 指向同一架构（Linux x86_64 / aarch64 均可，本机 JAR 无法加载原生库） |
| `ready` 返回 503 | 工具未注册完或 session 管理器未就绪，查 `/status` 与启动日志 |
| 客户端 POST `/message` 404 | base-path 下发的是绝对路径，确认客户端用 `new URL(endpoint, baseUrl)` 解析 |
| 重连失败 | grace period（60s）已过，需重新 `fh_connect`；或 token hash 与断连前不一致（防劫持） |
| `MEMORY`：`FH_RATE_LIMIT_MAX_KEYS` | 单 IP 跟踪数超限会 OOM，调大或缩短窗口 |
