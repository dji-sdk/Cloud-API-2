## 1. 仓库布局

Demo 后端相关代码集中在 `backend/`，与前端 `frontend/` 平级：

```text
fov-demo/
├── docs/                          # 需求与方案文档
├── backend/
│   ├── README.md
│   ├── docker/
│   │   └── oryx/                  # Oryx 独立部署（与 Java 进程分离）
│   │       ├── docker-compose.yml
│   │       └── README.md
│   └── fhsdk-demo-server/         # Spring Boot + FHSDK BFF
│       ├── pom.xml
│       ├── README.md
│       └── src/
│           └── main/
│               ├── java/com/dji/fhsdk/demo/
│               │   ├── FhsdkDemoApplication.java
│               │   ├── config/          # WebSocket、CORS、FHSDK 配置
│               │   ├── controller/      # REST 入口
│               │   ├── websocket/       # TelemetryWebSocket + 会话绑定
│               │   ├── service/         # 业务服务（见下表）
│               │   ├── fhsdk/           # FHSDK 封装、回调 → DTO
│               │   └── model/           # API / WS 消息 DTO
│               └── resources/
│                   ├── application.yml
│                   └── application-local.yml.example
└── frontend/                      # 见 2_前端方案.md
```

**原则**：`fhsdk-demo-server` 与 `docker/oryx` **分开目录、分开进程**；Java 只通过 WHIP/WHEP 与 Oryx 通信，不把流媒体栈打进 Spring Boot 镜像。

## 2. 进程与部署拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  fhsdk-demo-server (Spring Boot)       │
                    │  :8080 REST + WS                     │
                    │  ├─ FHSDK Java                       │
                    │  ├─ LiveModule → H.264               │
                    │  └─ FFmpeg 子进程 → WHIP 推流          │
                    └──────────────┬──────────────────────┘
                                   │ WHIP（WebRTC）
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  docker/oryx (Oryx / SRS)            │
                    │  :2022 WHIP/WHEP  :8000/udp WebRTC   │
                    └──────────────┬──────────────────────┘
                                   │ WHEP（浏览器）
                                   ▼
                              Vue 前端
```

| 组件 | 职责 | 默认端口 |
|------|------|----------|
| `fhsdk-demo-server` | SDK、订阅、REST/WS、FFmpeg WHIP 推流 | 8080 |
| `docker/oryx` | 接收 WHIP、对外 WHEP | 2022 / 8000/udp |

## 3. FHSDK 后端服务（fhsdk-demo-server）

### 3.1 技术栈

- Java 17+
- Spring Boot 3.x
- Jakarta WebSocket（`@ServerEndpoint` 或 `WebSocketHandler` + 注册器）
- FHSDK Java（`fhsdk/flight-hub-sdk.jar`，见 `fhsdk/README.md`，自行放置）
- FFmpeg ≥ 8.0（系统可执行文件，`-f whip` 管道推流）

### 3.2 包与模块映射

| 包 / 类 | 对应整体方案模块 | 职责 |
|---------|------------------|------|
| `SessionService` | SessionService | `POST /session/init`，FHSDK init |
| `DeviceSessionService` | DeviceSessionService | select / deselect、订阅生命周期 |
| `DeviceController` | — | `/devices`、`/devices/select` |
| `ControlService` | ControlService | DRC；stick（含 gimbalPitch）；`resetGimbal`；阶段 D′：飞行控制 |
| `PayloadService` | PayloadService | `listenLiveAvailableRange`、确认 Payload、WS `payload_range` |
| `LiveService` | LiveService | 开流 + FFmpeg WHIP；`SeiSubscriptionService` 订阅码流 SEI |
| `TelemetryPublisher` | TelemetryBridge | listen/subscribe → WS JSON |
| `ApiController` | — | REST 入口 |
| `TelemetryWebSocketHandler` | — | `/api/v1/ws/telemetry` |

### 3.3 设备生命周期（实现要点）

与 [整体方案 §5](./0_整体方案.md#5-会话与设备生命周期) 一致：

| 事件 | 实现 |
|------|------|
| `POST /devices/select` | 绑定 gateway、订阅慢通道 OSD、启动 Payload 监听（**不**自动开直播） |
| `GET /devices/payloads` | 返回当前可用 Payload 列表与是否已确认 |
| `POST /devices/payload` | 确认 `payloadIndex`（直播 / DRC 未开启时） |
| `POST /live/start` | `LiveService.startLive()`：拉流 + FFmpeg WHIP + **订阅 SEI** |
| `DELETE /live/stop` | `LiveService.stopLive()` |
| `POST /control/drc-link` | 要求 Payload 已确认；`ControlService.connectDrc()` → DRC 快激光 |
| `DELETE /control/drc-link` | 取消快激光订阅 → disconnect DRC |
| `DELETE /devices/select` | 先停直播、断 DRC → 取消全部订阅 → 清空上下文 |

`DeviceContext`（每 HttpSession 一个）字段：

```text
gatewaySn, droneSn, payloadIndex, payloadConfigured, selectedLiveInfo
drcConnected: boolean
listenIds / liveStreamListenId / payloadRangeListenId
FFmpegPipeStreamer streamer
whepPlayUrl, streamKey
```

`resetGimbal` 的 `payload_index` 解析顺序：请求体 → 已确认的 `DeviceContext.payloadIndex`。连接 DRC 时会尝试 `acquirePayloadControlAuthority`。

**阶段 D′（规划）**：在 `ControlService` / `ApiController` 增加一键起飞、急停、返航、取消返航等 REST 入口，映射对应 FHSDK API。

云台拖拽已通过对 `POST /control/stick` 下发 `yaw` + `gimbalPitch` 实现（与常见 stick_control 同类），无需单独 REST。

### 3.4 REST 接口

实现 [整体方案 §7.1](./0_整体方案.md#71-rest-api)，统一响应：

```json
{ "code": 0, "message": "ok", "data": { } }
```

### 3.5 WebSocket

实现 [整体方案 §7.2～§7.3](./0_整体方案.md#72-websocket-遥测)：

- 每条消息生成 `UUID.randomUUID()`
- SEI 按 SDK 回调频率推送前端；`ar` + `fov` 合并为一条
- 仅向已 `select` 且 WS 已连接的 HttpSession 推送

### 3.6 FFmpeg WHIP 推流

参考 `flight_hub_sdk_demo` 的 `FFmpegPipeStreamer`，输出改为 **WHIP**（不用 RTMP）：

```text
subscribeLiveStream(H.264) → stdin → ffmpeg -f whip → http://oryx:2022/rtc/v1/whip/?app=live&stream={streamKey}&secret=xxx
```

`streamKey` 建议：`demo_{gatewaySn}`，与 `GET /live/stream-url` 返回的 WHEP 参数一致。本机须 **FFmpeg ≥ 8.0**（WHIP muxer 自 8.0 "Huffman" 2025-08 进入主线，支持 `-f whip`）。

### 3.7 依赖 FHSDK 的方式

将 SDK 发行包中的 `flight-hub-sdk.jar` 放入 `fhsdk-demo-server/fhsdk/`（见 [`fhsdk/README.md`](../backend/fhsdk-demo-server/fhsdk/README.md)）。

`pom.xml` 通过 `systemPath` 引用：

```xml
<systemPath>${project.basedir}/fhsdk/flight-hub-sdk.jar</systemPath>
```

原生库（`.so` / `.dylib`）由 SDK JAR 内 `JniLibraryLoader` 加载。

## 4. Oryx 拉流服务（docker/oryx）

独立目录，**仅负责流媒体**，不包含业务逻辑。

```text
backend/docker/oryx/
├── docker-compose.yml    # 启动 Oryx
├── README.md             # 端口、WHEP URL 模板、排错
└── .env.example          # 可选：对外 IP、HTTP 端口
```

### 4.1 与 Java 服务的协作

| 项 | 约定 |
|----|------|
| WHIP 模板 | `oryx.whip-url-template: http://127.0.0.1:2022/rtc/v1/whip/?app=live&stream={streamKey}` |
| WHEP 模板 | `oryx.whep-url-template: http://127.0.0.1:2022/rtc/v1/whep/?app=live&stream={streamKey}` |
| 推流密钥 | `oryx.publish-secret`（Oryx 管理台 / `init-oryx.sh` 获取） |
| 流名 | `{streamKey}` 与 WHIP/WHEP 一致 |

### 4.2 启动

```bash
cd backend/docker/oryx
docker compose up -d
```

详细说明见 [`backend/docker/oryx/README.md`](../backend/docker/oryx/README.md)。

## 5. 配置与环境变量

`application.yml` 示例结构：

```yaml
server:
  port: 8080

fhsdk:
  address: http://YOUR_FH_SERVER_HOST
  port: "30812"
  notification-server: ws://YOUR_FH_SERVER_HOST:30812/openapi/v0.9/notification/ws/v1/notifications
  log-level: info
  log-to-console: true
  log-file-path: logs/flight_hub_sdk.log

oryx:
  whip-url-template: http://127.0.0.1:2022/rtc/v1/whip/?app=live&stream={streamKey}
  whep-url-template: http://127.0.0.1:2022/rtc/v1/whep/?app=live&stream={streamKey}
  publish-secret: ${ORYX_PUBLISH_SECRET:}

demo:
  stick-default-interval-ms: 50
  drone-payload-index: "81-0-0"   # 可选：前端下拉默认高亮；实际开流以 POST /devices/payload 为准
```

`demo.drone-payload-index` **可选**；未配置时前端仍可从 `listenLiveAvailableRange` 列表手动选择。

`ORYX_PUBLISH_SECRET` 等运行参数通过 `backend/docker/demo-server/.env` 注入。

## 6. 本地开发流程

```bash
# 1. 启动 Oryx
cd backend/docker/oryx && docker compose up -d

# 2. 配置环境变量（见 application-local.yml.example）

# 3. 启动 Java
cd backend/fhsdk-demo-server
mvn spring-boot:run

# 4. 健康检查
curl -X POST http://localhost:8080/api/v1/session/init
curl http://localhost:8080/api/v1/devices
```

前端开发时 Vite proxy → `http://localhost:8080`（`/api` + WS）；WHEP 经 `/oryx` 代理到 Oryx `:2022`。
