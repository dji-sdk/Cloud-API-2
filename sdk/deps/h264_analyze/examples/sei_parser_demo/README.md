# H264 SEI帧解析器 (DJI风格)

这是一个专门用于解析DJI H264码流中SEI（Supplemental Enhancement Information）帧的解析器，基于DJI Flight Hub SDK的解析逻辑实现。

## 功能特性

- 完全按照DJI Flight Hub SDK的解析逻辑实现
- 支持多子载荷SEI帧解析（一个SEI帧包含多个不同类型的子载荷）
- 自动移除防竞争字节（Emulation Prevention Bytes）
- 支持所有DJI SEI类型：EXT_SEI、FOV_SEI、AR_SEI、AI_SEI、ASSISTANT_SEI、END_TO_END_DELAY_SEI
- 显示SEI帧的详细信息：
  - 文件偏移位置
  - 帧大小（字节）
  - H.264 SEI载荷类型（245或102）
  - 子载荷数量和详细信息
  - 每个子载荷的完整数据（十六进制显示）

## H.264 SEI解析技术详解

### 1. H.264 NALU结构

```
H.264 NALU结构：
[起始码] [NALU头] [SEI载荷类型] [SEI载荷大小] [SEI载荷数据]
0000 0001    06        f5          7e        [DJI自定义数据...]
```

- **起始码**: `00 00 00 01` 或 `00 00 01`
- **NALU头**: `06` (SEI类型)
- **SEI载荷类型**: `f5` (245, DJI标识) 或 `66` (102, DJI标识)
- **SEI载荷大小**: 变长编码，符合H.264标准
- **SEI载荷数据**: DJI自定义的多子载荷结构

### 2. SEI载荷类型枚举

```cpp
enum class SeiType {
    ASSISTANT_SEI = 1,        // 助手SEI
    AR_SEI = 4,               // 增强现实SEI
    AI_SEI = 7,               // 人工智能SEI
    EXT_SEI = 9,              // 扩展SEI
    FOV_SEI = 10,             // 视场角SEI
    TIME_STAMP_SEI = 100,     // 时间戳SEI
    END_TO_END_DELAY_SEI = 155, // 端到端延迟SEI
};
```

### 3. DJI自定义SEI结构

DJI在标准H.264 SEI载荷数据中实现了自定义的多子载荷协议：

```
DJI SEI载荷数据：
[子载荷1] [子载荷2] [子载荷3] [子载荷4] [子载荷5] ...
```

每个子载荷的结构：
```
[类型低字节] [类型高字节] [长度低字节] [长度高字节] [数据N字节]
```

### 4. 子载荷解析逻辑

```cpp
// FlightHubSDK的processSei函数核心逻辑
for (int i = 0; i < length;) {
    // 1. 读取子载荷类型 (2字节，小端序)
    uint16_t payload_type = (data[i + 1] << 8) | data[i];
    
    // 2. 读取子载荷长度 (2字节，小端序)
    uint16_t payload_length = (data[i + 3] << 8) | data[i + 2];
    
    // 3. 计算数据起始和结束位置
    uint32_t data_start_index = i + 4;  // 跳过4字节头部
    uint32_t data_end_index = data_start_index + payload_length;
    
    // 4. 提取子载荷数据
    // 5. 移动到下一个子载荷
    i = data_end_index;
}
```

### 5. 防竞争字节处理

H.264标准要求处理防竞争字节（Emulation Prevention Bytes）：

**编码时**：如果原始数据出现 `00 00 03` 序列，需要插入额外的 `03` 字节
```
原始数据: 00 00 03
编码后:   00 00 03 03
```

**解码时**：移除 `00 00 03` 序列中的 `03` 字节
```
编码数据: 00 00 03 03
解码后:   00 00 03
```

### 解析过程详解

#### 1. H.264 NALU结构
```
位置0-3:   0000 0001    - NALU起始码
位置4:     06           - NALU头 (SEI类型)
位置5:     f5           - SEI载荷类型 (245, DJI标识)
位置6:     7e           - SEI载荷大小 (126字节)
```

#### 2. 第一个子载荷 (位置7-23)
```
位置7-10:  09 00 11 00
- 类型: (00 << 8) | 09 = 9 (EXT_SEI)
- 长度: (00 << 8) | 11 = 17字节
- 数据: 位置11-27 (包含防竞争字节)

原始数据: 00 00 03 00 00 03 00 00 03 00 00 ff ff ff ff 00 00 ff ff ff ff
解析后:   00 00 00 00 00 00 00 ff ff ff ff 00 00 ff ff ff ff
```

#### 3. 第二个子载荷 (位置28-36)
```
位置28-31: 06 00 09 00
- 类型: (00 << 8) | 06 = 6 (未知类型)
- 长度: (00 << 8) | 09 = 9字节
- 数据: 位置32-40

原始数据: 00 00 03 00 00 03 00 00 ff ff ff ff
解析后:   00 00 00 00 00 ff ff ff ff
```

#### 4. 第三个子载荷 (位置41-53)
```
位置41-44: 0a 00 0d 00
- 类型: (00 << 8) | 0a = 10 (FOV_SEI)
- 长度: (00 << 8) | 0d = 13字节
- 数据: 位置45-57

数据: 01 b4 25 00 00 47 1c 00 00 40 1a 00 00
```

#### 5. 第四个子载荷 (位置58-96)
```
位置58-61: 04 00 27 00
- 类型: (00 << 8) | 04 = 4 (AR_SEI)
- 长度: (00 << 8) | 27 = 39字节
- 数据: 位置62-100

数据: 21 fa ff c6 d4 3b 59 55 ff ff ff e7 f1 a4 35 03 00 be ff 01 a6 00 00 ff ff fd ff 00 00 00 00 00 00 00 00 01 a6 fd ff
```

#### 6. 第五个子载荷 (位置101-119)
```
位置101-104: 9b 00 13 00
- 类型: (00 << 8) | 9b = 155 (END_TO_END_DELAY_SEI)
- 长度: (00 << 8) | 13 = 19字节
- 数据: 位置105-123

数据: 9b 00 13 00 f1 15 0d ec 01 74 00 e6 e7 80 50 99 01 00 00
```

## 技术说明

- **完全基于DJI Flight Hub SDK**: 所有解析逻辑都直接照抄自DJI官方SDK
- **多子载荷支持**: 一个SEI帧可以包含多个不同类型的子载荷
- **防竞争字节处理**: 自动移除H.264防竞争字节（0x000003）
- **变长编码支持**: 支持H.264标准的变长编码SEI载荷长度解析
- **标准C++实现**: 使用C++11标准编写，不依赖平台特定接口
- **内存安全**: 使用std::vector管理内存，避免缓冲区溢出

## 数据结构

```cpp
struct SEISubPayload {
    uint16_t payload_type;      // 子载荷类型 (2字节)
    uint16_t payload_length;    // 子载荷长度 (2字节)
    std::vector<uint8_t> payload_data; // 子载荷数据
};

struct SEIFrame {
    uint32_t offset;        // SEI帧在文件中的偏移位置
    uint32_t size;          // SEI帧的大小（字节）
    uint8_t sei_payload_type;   // H.264标准SEI载荷类型 (0xf5 for DJI)
    std::vector<SEISubPayload> sub_payloads; // 子载荷数组
};
```

## 注意事项

1. **只解析第一个NALU**: 按照DJI的约定，SEI都在视频流的第一个NALU中
2. **只解析DJI SEI**: 只处理载荷类型为245(0xf5)和102(0x66)的SEI
3. **防竞争字节**: 必须正确处理H.264的防竞争字节机制
4. **字节序**: 子载荷长度使用小端序（little-endian）
5. **数据完整性**: 解析后的数据已经移除了防竞争字节，可以直接使用
